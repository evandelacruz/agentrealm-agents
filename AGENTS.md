# AGENTS.md

Rules for agents working in this repo. Read this first.

## What this is

Reference agents that play Agent Realm through its public API. Read [README.md](README.md), then [PLAN.md](PLAN.md).

The goal is for people to build their own agents for Agent Realm (agentrealm.gg), and for that to be easy and fun. Our agent is the starting point they copy, edit and grow, so it has to be easy to read and easy to change, not only correct.

## Where truth lives

| File | Role |
|---|---|
| [PLAN.md](PLAN.md) | Design, what the API allows today, server gaps, and the backlog: PR-sized items (A1, A2, …) with their dependencies, grouped under milestone headings (M0–M13). |
| [docs/PLAYABLE_AGENT_PLAN.md](docs/PLAYABLE_AGENT_PLAN.md) | Scope and done-when of the milestones M0, M4 and M6–M12. PLAN.md owns the item IDs and dependencies. |
| [docs/GAME_NOTES.md](docs/GAME_NOTES.md) | Game facts the plan relies on, each with its source. |
| [status.json](status.json) | Per-item work state. Not a source of truth. |
| The site's [docs](https://agentrealm.gg/docs) and [guides](https://agentrealm.gg/guides) | The API the agents play against. |
| `main` + open PRs | What shipped, what is in flight. |

There is no ticketing system. PLAN.md is the spec and the backlog.

**Read PLAN.md before asking for a decision.** The expensive failure is re-litigating something already settled.

`status.json` records what we currently think needs doing. Where it disagrees with PLAN.md, status is what is wrong.

## Boundaries

Decided. Do not cross without flagging prominently.

- **An ordinary API client.** HTTP only. Imports nothing from the server and never touches its databases. Something the API does not give is a server gap: write it into PLAN.md **Server gaps**, never build a side door.
- **Python 3.11+, standard library only.** The AI planner (M4, A35) is the one place a dependency may enter (the `anthropic` SDK, listed in `python/requirements.txt` and installed by `make setup`). It is on in every live run, but imported only when it runs, so `--no-planner` and `make test` stay standard library only. With `--no-planner` the built-in plan answers an op's `no_way_on` by exploring (A120), so a test run never freezes on a hold. The one exception is [`tools/conductor`](tools/conductor/README.md): ops tooling for building this repo, not part of an agent. It is Node 22+ and TypeScript on `@cursor/sdk`, and needs `CURSOR_API_KEY` for every command but `prs`.
- **Obeys the invariants a client can see.** At most one intent per tick, no standing orders, and when there is no decision it sends nothing.
- **Stays inside the call budget.** One request per character per tick, burst of 3, reads included (PLAN.md **What the API gives today**).

## Rules for agents

- Cite backlog IDs (A1, A50, …) in commits and PR bodies.
- Read the cited PLAN.md sections and this file before writing code.
- Write for the newcomer who will copy this agent: plain names, a short docstring on each state, one obvious place to add a behavior. Reviews flag anything that makes the agent harder to read or extend, the same as a bug.
- **Rules, not run patches (A87).** A fix found in a live run either generalizes a rule a state already has, or hands the situational call to the planner. It never adds a branch for the situation the run hit. Code comments state the rule in game terms; the run that found it is cited in the PLAN.md row and `docs/observations`, not in code. `make test` counts run citations (`run N` or `runs N`, any case) in agent source and the starter (`tests/test_architecture.py`) and fails a PR that adds one.
- The agent is character-agnostic: it plays whatever character it is handed at run time (A59). No live character name or id anywhere (code, configs, scripts, README, docs, status.json notes, tests; fixtures use obviously fake names), and characters are created only by an explicit `create` command.
- A live run needs exclusive use of its character. Another client's `tick` replaces the queue, so two clients on one character corrupt both runs' traces (A23 run 2). Do not start a run on a character that another session or agent is playing.
- Fight or flee is one decision per engagement (A94): `Memory.engagement`, synced once per decision in dispatch (`engagement.sync_engagement`). Every state and gate that asks whether to fight reads it through `engagement.fights` (the planner's `fight` op aside, A114), or `engagement.would_fight` for a hostile not yet in range. `survival.would_lose` is retired; never add a second fight test beside the engagement's. A fight decided on holds until it ends (A113): while Fight still has a target in it, the very hostile it would swing at or step toward (`fight.held_target`, passed to `sync_engagement`), and a chase after it closes the gap within `engagement.CHASE_PROBE_TICKS`; it ends when that target is dead, gone, forbidden or out of reach, or the decision turns. Never let a walking state resume between swings, and never add a second test of whom the fight goes on with.
- Room in a full pack is one rule (A102): `pack.make_room`, carried out for the states by `states.room`. Every state that picks up into a slot asks it. It never drops a supply the plan reserves (`pack.reserved_supplies`) or on a shop cell, and what to drop is only ever the planner's call (`drop` on `buy` and `fetch_item`). Never add a second drop choice or a code ranking of what is worth keeping.
- A stalled op is one rule (A104): `Plan.demote_current` with `stalled.below_progress`, the same for every op. An op on top that makes no progress for `PLAN_STALL_SECONDS` is remembered in `Memory.stalled_ops` and moved below the next op that can make progress (dropped when none can), and it does not come back on top, by a planner reply or by the ops above it ending, until `stalled.retry_reason` gives a reason. Never add a per-op stall branch. A stalled record is its map's only when its target names a cell there (`stalled.map_local`: x, y and no `map_id`, such as `break_block`, `use_block`, `explore_area` or a `travel` to a point); `remember`, `find` and `forget` then match on the map too. Any other op (`buy`, `equip`, `gather_gems` with no region, a `travel` that names its map) stays stalled on every map until `stalled.retry_reason` gives a reason.
- What failed where on the ground is one memory (A90): `NavStuckMemory.given_up`, a `stuck.GiveUp` per walk target by goal, map and cell (`stuck.goal_key`), backed off `BACKOFF_BASE_TICKS` doubled per give-up there, and aged by time alone. It is bounded only by forgetting lapsed give-ups past `GIVE_UPS_KEPT`, oldest first; a give-up still backed off is never forgotten. Every walk reads it (`stuck.is_backed_off`; Travel's destinations through `travel.resolve.given_up_travel`, blocks through `break_memory.given_up_blocks`); never add a second give-up list or a per-goal lapse. One escalation ladder (`navigation/stuck.py`) serves every walk, with nothing in it for a particular state; each of its levels makes progress only by beating the walk's best plan measure (`NavAttempt.net_best`, A125), and every level runs before the give-up. Pacing between two cells gives up every walk that made the moves, whichever state sent it and whichever attempt was active (`oscillation.walk_key`); a stuck walk whose step 2 block was given up leaves step 2, and the top op stalls only when its executor paced with a step that was no walk (`dispatch._stall_paced_op`). Each give-up raises a `stuck` trigger with `retry_at_tick`; whether to drop the goal is the planner's call.
- Where Gather works next is one search under one price (A105, A88): `states/gather.py` lists every place Gather may go for (`_targets`: grass, gem piles, the edge of unexplored ground) on one ground filter (`gather_safe.gather_ground`; no walk crosses `gather_safe.route_bar`), and prices each the same way: its walk (`_price`) plus its work (`GemOdds.work`), the actions there for the gems the op still needs at the yield there (`gem_yield.region_yield`, the map's `expected_yield` on unsampled ground). What is in reach is priced the same, with no walk. Which region, and whether to work near a hostile, are the planner's (`x, y`, `fight`). Never add a target kind with its own search, or a second walk-versus-yield pricing.
- Heal decides how to heal, never when it is worth leaving the op (A89): one line, the planner's `low_health` param (`healing.health_low`), decides when a carried potion is spent. Every Heal walk and pick is one price on one ground (`states/heal._walk_toward`, `_ground`), a block on the way a held item opens costed at its break; a given-up food cell lives in A90's give-up memory. What is sent after a refused or no-effect `Take` or `Use` on yourself is one table in the executor (`executor/supply_refusals.py`), filed by the runner; states only ask `can_try`. Never add a second health line, a Heal-only give-up, or a per-code retry branch in a state.
- Health rises only from potions and food (A124, A130, Evan: in Agent Realm "rest" means nothing): a potion, food, or food eaten on pickup, and a respawn at full health. There is no natural regeneration, on safe ground or anywhere, so Heal never walks to safe ground to wait for health, nothing measures regen, and no State line offers a rest; safe ground is a refuge from attack (Retreat, Flee), not a healing spot. Saved regen keys an older agent wrote are dropped at load (`knowledge_base.RETIRED_KEYS`). State `readiness` `to_close` shows how an unmet health check closes and its cost (`strategist.health_to_close`: food in sight, the cheapest potion seen for sale with its gem time, and the walk to the nearest known shop, which may not stock it: nothing records what each shop sells), and every gems-short figure gives its minutes by one rate (`strategist.minutes_at`); never tell the planner health recovers by itself, and never add a second time estimate. The health check counts held heals (A132): health plus the heal of the potions and food carried (`healing.held_heal`) must reach the bar, and `readiness` shows that sum (`health_with_held_heals`), so a drink never closes it and only takes one off the potion bar; the contract keeps a potion for an actual health need (the survival floor, a fight ahead), never a readiness bar. Never count health alone against the bar.
- A buy is done by one test (A106): `plan.goal_done`. It has paid (`Plan.paid_from`, the gems held when Shop last sent a Take for it, spent; a Take refused or gone stale unpays it, `shop.note_shop_result` and `shop.sync_shop`, so only a Take that landed pays) and the item is got: held, a chest that raised the pack (`supplies.chest_applied`, the same test State `held` shows), or used up on its Take (`supplies.eaten_on_pickup`, A112); else one more is held than its baseline. What a buy paid is the head op's own progress on the plan, like `held_before`: reset for every new head and kept by `Plan.snapshot`, so it needs no key. Keep per-op progress on the plan, never in `Memory` pointing at an op.
- Whether a level entrance is reachable is one check (A107): `navigation.entrance_routes`, sharing one `FINE_NODE_BUDGET` across every entrance in State. Never search per entrance outside it or grow its budget per entrance.
- Using a held item on yourself is one path (A108): `states/use_item.use_on_self`, for every consumable `supplies.used_on_self` names (a potion, a chest; a new self effect goes in `supplies.SELF_EFFECTS`). Heal and UseItem send through it. Never add a second `Arm` + `Use` self. Carry capacity rises only once a chest's `Use` went through (`loot.learn_chest_upgrade`), never on a `Take`. Carry capacity is derived at every inventory sync (`WorldModel.sync_carry_capacity`, A115) from the chest applied, a `carry_capacity_full` bound and the slots carried; never assume it or store it, only the applied chest the server cannot tell us.
- A buy needs a known seller (A110): State `no_seller_known` (`strategist.no_seller_line`) names the items a shop sells in some world (`supplies.sold_codes`) with no seller known, never items no shop sells; the contract tells the planner to find a seller or the item, not save gems for it. Never add a second test of what can be bought.
- A committed target is let go for its price by one rule (A109): `targets.outpriced`, once the walk ahead costs more than the rest of the walk it was last priced on (never a move another state made) and more than the cheapest other candidate by `OUTPRICE_RATIO` and `OUTPRICE_STEPS`. Gather applies it to every committed target (`gather._outpriced`). Never add a state's own repricing of a committed target.
- A reach-limited intent is sent only from a position the server has confirmed within reach (A116): one check, `reach.in_reach_from` (`Take`, the chest verbs, a `Use` on a target), applied where a reflex replaces a held walk whose Steps may have run unseen (`executor/held_queue.unconfirmed_send`). A new reach-limited verb goes in `reach.intent_reach`; never add a state's own reach test beside it.
- The executor sits below the states (A91): nothing under `executor/` imports from `states/`. A helper both need, such as the cost sets every walk plans with (`pathing.plan_sets`), lives below both, in `pathing` or `navigation`. `test_runner_owners.RunnerIsTheLoopTest` holds this.
- The way on, once the ground in reach is all seen, is the planner's call (A114): the safe default raises `no_way_on` and sends nothing, never stepping in place or parking beside a hostile, and State `map` (`strategist.map_lines`) shows the planner the ground cell by cell so it names the block, hostile or place. The safe default asks only when no frontier is left to walk to (`explore.NOTHING_TO_EXPLORE`); a frontier whose step is only taken for now holds the decision. Every ask goes through `states/ask.ask_the_planner`: one `no_way_on` per op, cell and reason (`Memory.no_way_on`, `ask.ask_key`), then the decision holds. Never add a state's own search for a block to open: an executor's goes through `way.open_the_way` (A120), Heal's through its one walk price (A89). Break refuses a `break_block` only on a cell with no block (walkable ground or no ground) or a block whose type's openers are known and exclude its capability; a type with no known opener may be tried, so its opener is learned.
- A walk on an op's behalf makes net progress toward its target (A125). Each leg ends below the estimate of the cost left that the walk has learned for where it stands, and that learning is kept when the corridor is searched again for the same goal (`NavSearchState.reset`). Every level of the A90 ladder counts progress only below the walk's best plan measure since it was taken up (`NavAttempt.net_best`, `stuck.observe`), so a fresh level never forgives a walk that stands no nearer, while a route round an obstacle is progress: past the path's end the measure reads the corridor search's estimate (`planner.rest_estimate`), not a straight line; a new way (`stuck.walk_again`) starts the bar again. The whole ladder runs, and once it gives up the executor clears the way or asks with how each level failed (`way.walk_given_up`). A detour is taken only when its gain beats its cost and is kept until its find is taken or a concrete reason drops it; never drop a detour for the time it has taken, and never add a second net-progress test beside `net_best`.
- Every op keeps its walk and clears its own way (A120, Evan: "if a goal or target is obstructed we need to try to unobstruct it, not get distracted"): one ladder, `states/way.py`. The executor's walk routes round; with no way round it opens the first block on the cheapest way a held item is known to open (`way.open_the_way`, `break_toward`; once the walk has no step only a way round over known ground counts, with unexplored ground beyond the block at fog cost, A129), or Break does at stuck step 2 of the op's own walk (Travel, Shop's walk to a shop or town, Level, Boss, by `way.OWNER_WALKS`; another walk's step 2 never stands in); a hostile on the way that the engagement would fight is the engagement's (Fight acts above every executor), and the walk routes round one it would not, or asks about it (A128, `pathing.op_walk_sets`), or a planner's `fight` op takes it (A114), never the executor's own fight; only then does it raise one `no_way_on` with why, `blocked_by` and `tried` (only this op's own attempts since it reached the top: searches, `Use`s, breaks recorded, never what is merely held nor an older break the knowledge base keeps, A129) and hold (`way.clear_the_way`, `ask.ask_the_planner`). An op with nothing to work on asks the same way, and any executor that sends nothing without asking is asked for once by the safe default's hold (`explore.hold_for`): every op whose executor cannot act asks. A shut way's searches are kept until the state, op, cell, tiles (`Tiles.revision`), what is held, or what lapses by time alone (the walks given up and still backed off, a block's, A90, or the op's own, A129, and the route learnings, `plan_sets`) change (`Memory.way_shut`). The survival reflexes act above every hold; a `fight` op's ask holds nothing, so Flee stays free. The safe default never stands in for an executor (`explore.HOLD_THEIR_WALK`, every executor but Explore): Explore moves only for `explore_area`, with no op, or as the `--no-planner` answer (`plan.builtin_way_on`). Never add a state that walks for another op's executor, and never let an executor that sends nothing fall through to a walk.
- A walk on an op's behalf keeps off the reach of the hostiles it has seen that the engagement would not fight (A128): `pathing.op_walk_sets` prices `hostile_ground.walk_reach` costly, leaving out each hostile in view that `engagement.would_fight` (its pack counted) and `never_attack` allows, which is the engagement's to take as the walk goes on; and `pathing.guided_step` (its `reach`) replans a kept path that comes to enter it and never walks a plan that still does, at any level of the stuck ladder (a held walk goes back to its first level, `nav_stuck.hold`); `bounded_step` walks hold the same way, with no give-up. The way an executor clears keeps to it too: a held walk may open a block (A129) only when the walk to that block stays out of the reach (`way.open_the_way`, `break_toward`'s `reach`), else it asks. Every op executor's walk takes its sets from `base.op_walk`, once per decision, and hands the same `reach` to the way it clears (Travel, Shop, Level's walk to an entrance and to the item a locked one needs, Loot, Investigate, Solve, Break); Fight's and Boss's, whose target is a hostile, and Explore's frontier walk do not; the executor then clears the way or asks the planner (`way.clear_the_way`). The engagement's estimate weighs every hostile that can reach the character, a pack counted whole (`survival.can_reach_us` in `engagement.decide`); never price one of a pack alone. A reflex walk under attack whose Steps the held queue may have made unsound takes the best open Step (`held_queue.open_step`), else Flee's cornered move (`brain.cornered_decision`), never a stop. Never add a walk's own hostile test beside `walk_reach`.
- A fight the planner chooses is the `fight` op (A114), carried out by Fight whatever the engagement would decide (the one exception to the A94 rule below); an `npc_type` fight is with the nearest of that type when it first comes into view, pinned by id from then on (`Plan.fight_npc`), so it is one fight; it is done once its NPC, seen since the op reached the top, is dead or out of sight, and dropped with why when its NPC was never in view or no swing or open step reaches it; no swing is ever sent from a safe tile (Fight steps off it first), and no step off safe ground is taken at the health floor (`fight.held_on_safe_ground`: the op is dropped with why instead). Cornered with no step, Flee drinks a heal that is due, else swings, else raises `cornered`: no state stands taking hits.
- Our death chests are one memory (A122): `WorldModel.death_chests`, every chest our deaths dropped, kept across runs per character (`knowledge_base.death_chests`) and dropped only once seen empty or gone in reach. State `death_chests` shows them to the planner, which goes back for one with `travel`; Recover takes back any in reach and walks only to one on a known-safe spot. Never keep a second death-chest record or let Pickup work one.
- Which weapon to arm is one rule (A99): `equip.weapon_to_arm`, by the job at hand (fight or cut), ordered by `equip.weapon_rank` (within the highest hunting-ground ceiling known first, then damage a second: `equip.damage_per_second`, a swing's damage over the weapon's attack cooldown, A123). An empty slot or a non-weapon in it ranks 0 (nothing armed swings nothing), so any held weapon within the ceiling is armed into it; the win estimate alone assumes such a slot swings as the starting knife (`survival.fighting_weapon`, A81). Every `Use` is paced by the cooldown of the supply in hand when it runs, converted at the world's tick rate (`executor.pacing.attack_cooldown_ticks` with `PlayContext.tick_hz`): the runner's single `Use`, Fight's and Boss's attack queues, and an `Arm` + `Use` (`states/intents.arm_and_use`: Gather's cutter, a drink). `pace_uses`, `build_attack_queue` and `arm_then_use` take the cooldown as a required argument; never pace a swing at a fixed interval. Equip, Gather and the planner's `upgrades_for_sale` read it; never add a second weapon ranking. The one exception today is Break, which picks the tool for a block's capability with `break_memory.pick_supply_for_capability` (not used up first, then armed, then code).
- Keep PLAN.md and README.md matching the code. A behavior change that leaves them describing the old one is not done.
- Run `make test` before pushing, and `make conductor-test` if you touched `tools/conductor`. The `test` GitHub Actions workflow runs both on every PR.
- Tests never read or write `python/.state` (A86): `python/tests/__init__.py` points `AGENTREALM_STATE_DIR` at a temp dir and fails the suite on any file operation there. `knowledge_base.WORLDS_DIR` and `supplies.CACHE_PATH` are bound at import, so a test that patches `config.STATE_DIR` must patch them too.
- Open PRs **ready for review, not draft**. If tooling defaults to draft, run `gh pr ready`.
- **Never merge.** Evan merges, and so does the supervisor ([`.claude/skills/agentrealm-agents-supervisor/SKILL.md`](.claude/skills/agentrealm-agents-supervisor/SKILL.md)). No other agent does.
- **Review verdict:** every pull request has two reviewers, set in [`.github/reviewers`](.github/reviewers): the Opus bot always, plus Cursor or the Sonnet bot. Only trusted reviewers count; anyone else's review is ignored. It is approved when both approved its current head, no trusted reviewer (a person included) rejected it, and no review is running. Open threads never block. Rule: [`agentrealm-agents-fixer`](.claude/skills/agentrealm-agents-fixer/SKILL.md) **The review verdict**. Only Evan edits `.github/reviewers`.
- Do not add dependencies, or change moderation or the call budget or pacing, without flagging prominently.
- If blocked by an open architecture, legal, or moderation question, an open design question, or a server gap, **halt and say why**. Do not invent. Check PLAN.md and the published docs first.
- Backlog items are PR-sized. If one still needs a second PR, ship a reviewable slice, mark the ID `partial` with a `remaining` note in `status.json`, and let the next pass continue it.
- In `status.json`, edit only the entries of the IDs your PR covers, and keep the blank line between entries. Two PRs on different IDs then never touch adjacent lines, so they do not conflict. The exception is a new ID appended after the last entry: it adds a comma to that entry's line, so it can conflict with a PR that edits that entry. Merge `main` and keep both.

## Writer lock

`conductor:working` is the writer lock for **implementers and fixers** (Cursor or Claude Code). Reviewers never take it.

- Claim it when you start writing. Release it when you finish (after the push, PR ready) or if the spawn that claimed it failed before the agent started. One exception: a fixer that declines every finding and has nothing to push keeps it and hands the PR to Evan ([`agentrealm-agents-fixer`](.claude/skills/agentrealm-agents-fixer/SKILL.md) **Declined everything**).
- The claim is check-then-add, not atomic. Two writers that start at the same moment can both claim it.
- Skip a PR that already has the label. Do not add a second writer. Do not delete a lock you did not claim in this session.
- Cursor `status` listing an implementer as `finished` means that worker should already have released. If the label is still on the PR, another worker may hold it (Claude Code fixers use the same label and do not appear in that list) or the holder crashed. Leave the label and tell Evan. Do not treat "Cursor finished" as permission to clear it.
