# AGENTS.md

Rules for agents working in this repo. Read this first.

## What this is

Reference agents that play Agent Realm through its public API. Read [README.md](README.md), then [PLAN.md](PLAN.md).

The goal is for people to build their own agents for Agent Realm (agentrealm.gg), and for that to be easy and fun. Our agent is the starting point they copy, edit and grow, so it has to be easy to read and easy to change, not only correct.

**Three agents, three names.** Each agent in this repo has a short name that is also how commits, run notes and observations refer to it, and one meta file under [`docs/agents/`](docs/agents/) with the same six fields: name, plays to, how it thinks, temperament, will not, lineage. Grinding Gary (`gary`, `python/agentrealm_agent/`) is the full agent grown run by run: his planner (`strategist`, `plan`, `brain`, `cells`), his `runner`, his `states`, `shop`, his command line and his milestone acceptance gates. Ladder Lorraine (`lorraine`, `python/ladder/`, M14) is the goal-tree agent. Starter Stan (`stan`, `python/starter_agent.py`) is the one-file starter. The plumbing they share is the agent ADK, `python/agentrealm_adk/` (A149): the API client, `WorldModel`, the knowledge base, pathing and navigation, the executor, travel, the reflex helpers, the reference data, and the command line's parser and `status` self line (`cli`). Gary and Lorraine import from `agentrealm_adk` directly; there are no re-export stubs. The ADK imports neither agent, and Lorraine imports nothing of Gary's (`agentrealm_agent`); the architecture test (`tests/test_architecture.py` `ImportLineTest`) holds both lines on the import closure: every ADK module's, with the ADK's import statements (A149), and her package's (A138). A helper an agent and the ADK share lives in the ADK: plan-shaped helpers (`GoalOp`, `explore_targets`) in `targets`, safe-ground tests (`hostiles_near`, `is_safe_ish`) in `hostile_ground`. Never add an ADK import of `agentrealm_agent`, `ladder` or `starter_agent`. All three play any character, and you pick one at run time.

## Boundaries

Decided. Do not cross without flagging prominently.

- **An ordinary API client.** HTTP only. Imports nothing from the server and never touches its databases. Something the API does not give is a server gap: write it into PLAN.md **Server gaps**, never build a side door.
- **Python 3.11+, standard library only.** The AI planner (M4, A35) is the one place a dependency may enter (the `anthropic` SDK, listed in `python/requirements.txt` and installed by `make setup`). It is on in every live run, but imported only when it runs, so `--no-planner` and `make test` stay standard library only. With `--no-planner` the built-in plan answers an op's `no_way_on` by exploring (A120), so a test run never freezes on a hold. The one exception is [`tools/conductor`](tools/conductor/README.md): ops tooling for building this repo, not part of an agent. It is Node 22+ and TypeScript on `@cursor/sdk`, and needs `CURSOR_API_KEY` for every command but `prs`.
- **Obeys the invariants a client can see.** At most one intent per tick, no standing orders, and when there is no decision it sends nothing.
- **Stays inside the call budget.** One request per character per tick, burst of 3, reads included (PLAN.md **What the API gives today**).

## Rules for agents

- Cite backlog IDs (A1, A50, …) in commits and PR bodies.
- Read the cited PLAN.md sections and this file before writing code.
- Write for the newcomer who will copy this agent: plain names, a short docstring on each state, one obvious place to add a behavior. Reviews flag anything that makes the agent harder to read or extend, the same as a bug.
- **Rules, not run patches (A87).** A fix found in a live run either generalizes a rule a state already has, or hands the situational call to the planner. It never adds a branch for the situation the run hit. Code comments state the rule in game terms; the run that found it is cited in the PLAN.md row and `docs/observations`, not in code. `make test` counts run citations (`run N` or `runs N`, any case) in agent source and the starter (`tests/test_architecture.py`) and fails a PR that adds one.
- The agent is character-agnostic: it plays whatever character it is handed at run time (A59). No live character name or id anywhere (code, configs, scripts, README, docs, status.json notes, tests; fixtures use obviously fake names), and characters are created only by an explicit `create` command.
- A live run needs exclusive use of its character. Another client's `tick` replaces the queue, so two clients on one character corrupt both runs' traces (A23 run 2). Do not start a run on a character that another session or agent is playing.
- Fight or flee is one decision per engagement (A94): `Memory.engagement`, synced once per decision in dispatch (`engagement.sync_engagement`). Every state and gate that asks whether to fight reads it through `engagement.fights` (the planner's `fight` op aside, A114), or `engagement.would_fight` for a hostile not yet in range, and with `at` for the decision it would make standing on another cell (`way.land_to_fight`, A151): every reader of our position in the estimate takes it (`decide`, `combat_group`, `can_reach_us`, `swings_nothing`), never a world copied with its position overwritten. The estimate prices each hostile at the health it has left (`survival.health_left`, A162): a hostile never heals while it lives, so the damage it has taken is kept until it dies (`WorldModel.npc_damage`, from every `NPCDamaged` seen), and `survival.UNKILLED_HOSTILE_HEALTH` applies only to one never hit (a boss is priced at it as before; its served health is A163's); never reset it between fights. `survival.would_lose` is retired; never add a second fight test beside the engagement's. A fight decided on holds until it ends (A113): while Fight still has a target in it, the very hostile it would swing at or step toward (`fight.held_target`, passed to `sync_engagement`), and a chase after it closes the gap within `engagement.CHASE_PROBE_TICKS`; it ends when that target is dead, gone, forbidden or out of reach, or the decision turns. A fight decision turns only at the survival floor against the hostiles it weighs, when none of them is left in view, or when a hostile the estimate had not weighed joins (`engagement.fight_holds`, A136), and whether Fight can close is one walk (`fight.close_step`, the shortest walk to weapon reach over ground fixed round the target (`APPROACH_RADIUS`, or perception when further), never a greedy step nor a bound measured from where Fight stands), so Fight and Flee never take turns on the same facts. Never let a walking state resume between swings, and never add a second test of whom the fight goes on with.
- Room in a full pack is one rule (A102): `pack.make_room`, carried out for the states by `states.room`. Every state that picks up into a slot asks it. It never drops a supply the plan reserves (`pack.reserved_supplies`) or on a shop cell, and what to drop is only ever the planner's call (`drop` on `buy` and `fetch_item`). Never add a second drop choice or a code ranking of what is worth keeping.
- A stalled op is one rule (A104): `Plan.demote_current` with `stalled.below_progress`, the same for every op. An op on top that makes no progress for `PLAN_STALL_SECONDS` is remembered in `Memory.stalled_ops` and moved below the next op that can make progress (dropped when none can), and it does not come back on top, by a planner reply or by the ops above it ending, until `stalled.retry_reason` gives a reason. Never add a per-op stall branch. A stalled record is its map's only when its target names a cell there (`stalled.map_local`: x, y and no `map_id`, such as `break_block`, `use_block`, `explore_area` or a `travel` to a point); `remember`, `find` and `forget` then match on the map too. Any other op (`buy`, `equip`, `gather_gems` with no region, a `travel` that names its map) stays stalled on every map until `stalled.retry_reason` gives a reason.
- What failed where on the ground is one memory (A90): `NavStuckMemory.given_up`, a `stuck.GiveUp` per walk target by goal, map and cell (`stuck.goal_key`), backed off `BACKOFF_BASE_TICKS` doubled per give-up there, and aged by time alone. It is bounded only by forgetting lapsed give-ups past `GIVE_UPS_KEPT`, oldest first; a give-up still backed off is never forgotten. Every walk reads it (`stuck.is_backed_off`; Travel's destinations through `travel.resolve.given_up_travel`, blocks through `break_memory.given_up_blocks`); never add a second give-up list or a per-goal lapse. One escalation ladder (`navigation/stuck.py`) serves every walk, with nothing in it for a particular state; each of its levels makes progress only by beating the walk's best plan measure (`NavAttempt.net_best`, A125), and every level runs before the give-up. Pacing between two cells gives up every walk that made the moves, whichever state sent it and whichever attempt was active (`oscillation.walk_key`); a stuck walk whose step 2 block was given up leaves step 2, and the top op stalls only when its executor paced with a step that was no walk (`dispatch._stall_paced_op`). Two or more states pacing with steps that are no walk and nothing coming of it are settled by the same guard (A136): the side going against the engagement's decision, else the last to step, is benched (never the side carrying out the decision, Fight while it says fight and Flee or Retreat while it says flee, and never Retreat, which runs at the survival floor; when only those paced, the planner is asked once per flip episode) (`oscillation.bench`, `oscillation.benched`) until its cool-down ends or the decision changes, and the same flip again asks the planner (`pacing`); never add a state's own anti-flip branch. Each give-up raises a `stuck` trigger with `retry_at_tick`; whether to drop the goal is the planner's call.
- Where Gather works next is one search under one price (A105, A88): `states/gather.py` lists every place Gather may go for (`_targets`: grass, gem piles, the edge of unexplored ground) on one ground filter (`gather_safe.gather_ground`; no walk crosses `gather_safe.route_bar`), and prices each the same way: its walk (`_price`) plus its work (`GemOdds.work`), the actions there for the gems the op still needs at the yield there (`gem_yield.region_yield`, the map's `expected_yield` on unsampled ground). What is in reach is priced the same, with no walk. Which region, and whether to work near a hostile, are the planner's (`x, y`, `fight`). Never add a target kind with its own search, or a second walk-versus-yield pricing.
- Heal decides how to heal, never when it is worth leaving the op (A89): one line, the planner's `low_health` param (`healing.health_low`), decides when a carried potion is spent. Every Heal walk and pick is one price on one ground (`states/heal._walk_toward`, `states/food.ground`), a block on the way a held item opens costed at its break; a given-up food cell lives in A90's give-up memory. What is sent after a refused or no-effect `Take` or `Use` on yourself is one table in the executor (`executor/supply_refusals.py`), filed by the runner; states only ask `can_try`. Never add a second health line, a Heal-only give-up, or a per-code retry branch in a state. A potion is for a fight (A135): every drink (Heal, Flee cornered, Retreat losing ground, the planner's `use_item`) asks `healing.spend_potion`, which out of combat (`healing.in_combat`: under attack, a hostile in range, a boss fight, inside a level, or a fight op next) drinks only at the low line once no food near can be had; in combat it drinks at the low line, when ordered, or when the drink turns the engagement, checked against the held decision (`engagement.drink_turns_fight`, A96): a fight held on lower odds (A136) is already fight, so no potion goes only to lift it back over the bar, but a held fight still drinks when the drink lifts it from below break-even to above it. Food near is one test: `healing.food_near` lists the candidates (food lying within `FOOD_REACH`, and blocks that drop food, `supplies.BLOCK_FOOD`, a held item opens without being used up), State `food_near` shows them, and `states/food.food_route` prices them by Heal's walk; Heal goes for that route (a block only out of combat) and drinks once it could act on none; UseItem asks `spend_potion` too, ordered, with a fight next and that route (`use_item.potion_refused`, which only names why), and refuses the drink out of combat while the route exists or above the low line. Only Heal commits to a food target; any other reader of the route only looks. Every walk time shown is `healing.walk_seconds`. Never add a second test of when a potion is worth drinking or of what food is near.
- Health rises only from potions and food (A124, A130, Evan: in Agent Realm "rest" means nothing; Manual §11 Food and potions): a potion, food, or food eaten on pickup, a respawn at full health, and a boss clear, which refills it to the maximum. The Manual says food is eaten on pickup and never carried; the code still counts carried food (`healing.held_heal`, Heal's carried-food branch) until A155. There is no natural regeneration, on safe ground or anywhere, so Heal never walks to safe ground to wait for health, nothing measures regen, and no State line offers a rest; safe ground is a refuge from attack (Retreat, Flee), not a healing spot. Saved regen keys an older agent wrote are dropped at load (`knowledge_base.RETIRED_KEYS`). State `readiness` `to_close` shows how an unmet health check closes and its cost (`strategist.health_to_close`: food in sight, the cheapest potion seen for sale with its gem time, and the walk to the nearest known shop, which may not stock it: nothing records what each shop sells), and every gems-short figure gives its minutes by one rate (`strategist.minutes_at`); never tell the planner health recovers by itself, and never add a second time estimate. The health check counts held heals (A132): health plus the heal of the potions and food carried (`healing.held_heal`) must reach the bar, and `readiness` shows that sum (`health_with_held_heals`), so a drink never closes it and only takes one off the potion bar; the contract keeps a potion for an actual health need (the survival floor, a fight ahead), never a readiness bar. Never count health alone against the bar.
- A buy is done by one test (A106): `plan.goal_done`. It has paid (`Plan.paid_from`, the gems held when Shop last sent a Take for it, spent; a Take refused or gone stale unpays it, `shop.note_shop_result` and `shop.sync_shop`, so only a Take that landed pays) and the item is got: held, a chest that raised the pack (`supplies.chest_applied`, the same test State `held` shows), or used up on its Take (`supplies.eaten_on_pickup`, A112); else one more is held than its baseline. What a buy paid is the head op's own progress on the plan, like `held_before`: reset for every new head and kept by `Plan.snapshot`, so it needs no key. Keep per-op progress on the plan, never in `Memory` pointing at an op.
- Whether a level entrance is reachable is one check (A107): `navigation.entrance_routes`, sharing one `FINE_NODE_BUDGET` across every entrance in State. Never search per entrance outside it or grow its budget per entrance.
- Using a held item on yourself is one path (A108): `states/use_item.use_on_self`, for every consumable `supplies.used_on_self` names (a potion, a chest; a new self effect goes in `supplies.SELF_EFFECTS`). Heal and UseItem send through it. Never add a second `Arm` + `Use` self. Carry capacity rises only once a chest's `Use` went through (`loot.learn_chest_upgrade`), never on a `Take`. Carry capacity is derived at every inventory sync (`WorldModel.sync_carry_capacity`, A115) from the chest applied, a `carry_capacity_full` bound and the slots carried; never assume it or store it, only the applied chest the server cannot tell us.
- What looks out of place is one detector (A134): `oddities.is_odd`, a breakable block alone among another type in its 7x7 neighbourhood, over the terrain the agent remembers. State `oddities` shows the nearest few, remembered in the knowledge base and judged again on every look (one whose block still shows but no longer passes `is_odd` is dropped; one broken stays until it is back), with their tries read from break memory; whether to break one is the planner's `break_block`. Never add a second odd-block test or a state that breaks one by itself.
- A buy needs a known seller (A110, A131): `sellers.sellers_of` is the one seller test: a shop cell last seen selling the item (`record_shop_cell` keeps what each cell sells; one reached without it forgets it, `forget_sale`), a sign, scroll or NPC line with a phrase naming it and a gem price, or the place the `buy` op names (`x`, `y`, `map_id`, all three). A price seen with no place is no seller, and neither is a clue's or a buy's place searched round without the item (`note_not_sold`, kept in the knowledge base with its tick). The record lapses on newer evidence the item is sold: a clue offering it found after the search, anywhere (`sellers.lapse_not_sold`, run after each clue is captured), or a shop seen selling it (`record_shop_cell`). State `sellers` and `no_seller_known` resolve the stack's buy ops the same way, each op's own place included. A shop cell saved before A131, with no `sells`, is an `unchecked` seller of every item a price was seen for, tried only after every other seller and checked off once in sight. Shop walks only toward a seller, the cheapest walk first, searching round a clue's or the op's place once there, never to a shop that does not sell the item, and the sellers this buy reached are its head progress (`Plan.sellers_searched`), never `Memory`; a reply's buy with none is left out with why (`sellers.refuse_unsold`), and Shop drops one that reaches the top. State `no_seller_known` (`strategist.no_seller_line`) names the items a shop sells in some world (`supplies.sold_codes`) with no seller known, never items no shop sells, and State `sellers` (`sellers.sellers_line`) where each is sold and roughly how far; the contract tells the planner to find a seller or the item, not save gems for it. Never add a second test of what can be bought or a walk to a shop that does not sell it.
- A committed target is let go for its price by one rule (A109): `targets.outpriced`, once the walk ahead costs more than the rest of the walk it was last priced on (never a move another state made) and more than the cheapest other candidate by `OUTPRICE_RATIO` and `OUTPRICE_STEPS`. Gather applies it to every committed target (`gather._outpriced`). Never add a state's own repricing of a committed target.
- A reach-limited intent is sent only from a position the server has confirmed within reach (A116): one check, `reach.in_reach_from` (`Take`, the chest verbs, a `Use` on a target), applied where a reflex replaces a held walk whose Steps may have run unseen (`executor/held_queue.unconfirmed_send`). A new reach-limited verb goes in `reach.intent_reach`; never add a state's own reach test beside it.
- The executor sits below the states (A91): nothing under `executor/` imports from `states/`. A helper both need, such as the cost sets every walk plans with (`pathing.plan_sets`), lives below both, in `pathing` or `navigation`. `test_runner_owners.RunnerIsTheLoopTest` holds this.
- The way on, once the ground in reach is all seen, is the planner's call (A114): the safe default raises `no_way_on` and sends nothing, never stepping in place or parking beside a hostile, and State `map` (`strategist.map_lines`) shows the planner the ground cell by cell so it names the block, hostile or place. The safe default asks only when no frontier is left to walk to (`explore.NOTHING_TO_EXPLORE`); a frontier whose step is only taken for now holds the decision. Every ask goes through `states/ask.ask_the_planner`: one `no_way_on` per op, cell and reason (`Memory.no_way_on`, `ask.ask_key`), then the decision holds. Never add a state's own search for a block to open: an executor's goes through `way.open_the_way` (A120), Heal's through its one walk price (A89). Break refuses a `break_block` only on a cell with no block (walkable ground or no ground) or a block whose type's openers are known and exclude its capability; a type with no known opener may be tried, so its opener is learned.
- A walk on an op's behalf makes net progress toward its target (A125). Each leg ends below the estimate of the cost left that the walk has learned for where it stands, and that learning is kept when the corridor is searched again for the same goal (`NavSearchState.reset`). Every level of the A90 ladder counts progress only below the walk's best plan measure since it was taken up (`NavAttempt.net_best`, `stuck.observe`), so a fresh level never forgives a walk that stands no nearer, while a route round an obstacle is progress: past the path's end the measure reads the corridor search's estimate (`planner.rest_estimate`), not a straight line; a new way (`stuck.walk_again`) starts the bar again. The whole ladder runs, and once it gives up the executor clears the way or asks with how each level failed (`way.walk_given_up`). A detour is taken only when its gain beats its cost and is kept until its find is taken or a concrete reason drops it; never drop a detour for the time it has taken, and never add a second net-progress test beside `net_best`.
- Every op keeps its walk and clears its own way (A120, Evan: "if a goal or target is obstructed we need to try to unobstruct it, not get distracted"): one ladder, `states/way.py`. The executor's walk routes round; with no way round it opens the first block on the cheapest way a held item is known to open (`way.open_the_way`, `break_toward`; once the walk has no step only a way round over known ground counts, with unexplored ground beyond the block at fog cost, A129), or Break does at stuck step 2 of the op's own walk (Travel, Shop's walk to a shop or town, Level, Boss, by `way.OWNER_WALKS`; another walk's step 2 never stands in); a hostile on the way that the engagement would fight is the engagement's (Fight acts above every executor), and the walk routes round one it would not, passes its ground when that is the only way and health covers it, or lands where it meets the hostile for the engagement to take (A128, A146, A151, A162, `pathing.op_walk_sets`, `way.land_to_fight`), else asks about it, or a planner's `fight` op takes it (A114), never the executor's own fight; only then does it raise one `no_way_on` with why, `blocked_by` and `tried` (only this op's own attempts since it reached the top: searches, `Use`s, breaks recorded, never what is merely held nor an older break the knowledge base keeps, A129) and hold (`way.clear_the_way`, `ask.ask_the_planner`). An op with nothing to work on asks the same way, and any executor that sends nothing without asking is asked for once by the safe default's hold (`explore.hold_for`): every op whose executor cannot act asks. A shut way's searches are kept until the state, op, cell, tiles (`Tiles.revision`), what is held, or what lapses by time alone (the walks given up and still backed off, a block's, A90, or the op's own, A129, and the route learnings, `plan_sets`) change (`Memory.way_shut`). The survival reflexes act above every hold; a `fight` op's ask holds nothing, so Flee stays free. The safe default never stands in for an executor (`explore.HOLD_THEIR_WALK`, every executor but Explore): Explore moves only for `explore_area`, with no op, or as the `--no-planner` answer (`plan.builtin_way_on`). Never add a state that walks for another op's executor, and never let an executor that sends nothing fall through to a walk.
- A walk on an op's behalf keeps off the reach of the hostiles it has seen that the engagement would not fight (A128): `pathing.op_walk_sets` prices `hostile_ground.walk_reach` costly, leaving out each hostile in view that `engagement.would_fight` (its pack counted) and `never_attack` allows, which is the engagement's to take as the walk goes on; and `pathing.guided_step` (its `reach`) replans a kept path that comes to enter it and never walks a plan that still does, at any level of the stuck ladder (a held walk goes back to its first level, `nav_stuck.hold`); `bounded_step` walks hold the same way, with no give-up. The one pass (A146) is the `pathing.HostileReach` that `op_walk_sets` returns, asked only by the one reach test `pathing.enters_reach` with the walk's own goal (`guided_step`'s leg target, every level and a reveal step included, and `bounded_step`'s target; a walk that names no goal never passes): it passes when no plan that keeps out of the reach gets to the goal (`HostileReach.only_way`, the goal itself left out of the reach, one search per position and goal) and `pathing.covers_pass` holds. Flee and Retreat run as now: a pass happens only on a walk the engagement does not say to flee from, so none while the engagement says flee. Every hostile it passes is priced as a chaser (A162, Manual §11 Hostiles: it steps to the neighbouring block that brings it closest and stands still where none does, `hostile_ground.chase`, from where it stands or was last seen, at our pace), and no pass comes within `hostile_range` of where the chase puts it (where the engagement, which would not fight it, says flee), so a chaser in the open is never passed and only one the ground stops is; the hits each is expected to deal while the chase keeps it within its ground's radius of us (`survival.expected_damage`), none on a known safe block, less what the heals carried win back on it (`pathing.heal_on_pass`), must leave health above Retreat's floor (`survival.health_floor`). Held heals count toward a pass only where they can be used: none on a pass with a water cell unless the fording supply is worn (an `Arm` there would strand, A133), each one costing its `Arm` and its `Use`, a tick each and no cooldown (a `Use` on yourself is no swing, A153), in ticks of hits, and never above the health the pass starts with. `covers_pass` takes the same `walk_ground` the reach was built from. Seen or remembered is the same (A151): the ground is each known hostile's (`hostile_ground.walk_ground`: one in view's reach and margin, one out of view's bar round its last-seen cell; a hostile keeps no post, A162), known safe blocks left out, since nothing hurts there (`hostile_ground.off_safe`), a remembered one priced from the threat table as one in view; remembered ground still bars every walk that has a way round. When the pass is not covered and the one hostile whose ground shuts the way is in view and not forbidden, and a land cell within its range is reached on a way where the chase first brings it within range of us on land and the engagement would fight it from that cell (`engagement.would_fight` with `at`, `way._meeting`, A162: a chaser that meets the walk on water is never landed for), the executor's way-clearing lands there (`way.land_to_fight`, its own `bounded_step` walk, searched only while the way is not known shut, `Memory.way_shut`) and ashore the engagement takes it, Fight arming the weapon (A133); only with neither does it ask, and `blocked_by` names each hostile whose ground the way crosses with its cell (`ask.what_blocks`, handed the op walk's `reach` so `op_walk` runs once a decision), and a hostile the engagement would fight whose range reaches the way, never the generic "no known way". The way an executor clears keeps to it too: a held walk may open a block (A129) only when the walk to that block stays out of the reach (`way.open_the_way`, `break_toward`'s `reach`), else it asks. Every op executor's walk takes its sets from `base.op_walk`, once per decision, and hands the same `reach` to the way it clears (Travel, Shop, Level's walk to an entrance and to the item a locked one needs, Loot, Investigate, Solve, Break); Fight's and Boss's, whose target is a hostile, and Explore's frontier walk do not; the executor then clears the way or asks the planner (`way.clear_the_way`). The engagement's estimate weighs every hostile that can reach the character, a pack counted whole (`survival.can_reach_us` in `engagement.decide`); never price one of a pack alone. ## Writer lock

`conductor:working` is the writer lock for **implementers and fixers** (Cursor or Claude Code). Reviewers never take it.

- Claim it when you start writing. Release it when you finish (after the push, PR ready) or if the spawn that claimed it failed before the agent started. One exception: a fixer that declines every finding and has nothing to push keeps it and hands the PR to Evan ([`agentrealm-agents-fixer`](.claude/skills/agentrealm-agents-fixer/SKILL.md) **Declined everything**).
- The claim is check-then-add, not atomic. Two writers that start at the same moment can both claim it.
- Skip a PR that already has the label. Do not add a second writer. Do not delete a lock you did not claim in this session.
- Cursor `status` listing an implementer as `finished` means that worker should already have released. If the label is still on the PR, another worker may hold it (Claude Code fixers use the same label and do not appear in that list) or the holder crashed. Leave the label and tell Evan. Do not treat "Cursor finished" as permission to clear it.
