# Reference agent: plan

A test agent for creating characters and running them against an Agent Realm world. It is also the seed of the public [reference agent](https://agentrealm.gg/) the site quick start calls for: Python first, an example rather than an SDK.

It is outside the formal backlog. It is built interactively and changes as the API does.

## Boundaries

- **An ordinary API client.** HTTP only. It imports nothing from the Go code and never touches Postgres, Redis, or NATS. If it needs something the API does not give, that is a server gap, written down below, not a side door.
- **Python 3.11+, standard library only.** No install step beyond Python. The AI planner (M4, A35) is the one place a dependency may enter (the `anthropic` SDK), imported only when the planner runs, so `--no-planner` and `make test` stay standard library only.
- **Obeys the invariants a client can see.** At most one intent per tick, no standing orders, and when there is no decision it sends nothing.

## Architecture: AI plans, state machine executes

The agent is a fast algorithmic layer under a slower planner (A61, the redirect of 2026-10-06). The planner decides *what* to do; the state machine decides *how*, tick by tick. No state picks its own goal.

- **The plan stack** comes from the AI planner (the strategist, A35), on in every live run; directives `goals` (manual steering) outrank it. With the planner on nothing else fills the stack. Only in the `--no-planner` test mode does the built-in planner turn `policy.goals` into ops (`plan.builtin_goals`). Its top op is the one thing being done.
- **Reflexes** act on what is happening now, whatever the plan says: Sync, Downed, Escape, Retreat, Heal, Fight, Flee, Pickup (a supply underfoot or adjacent), Recover, Detour (a valuable in view worth the steps it adds to the walk, A71, A73) and Greet (a one-tick hello to a likely helper in sight not yet spoken to, sent only at a decision window, never by the held-queue probe, A65).
- **Executors** run only to carry out the top op (`plan.OP_STATE`): Equip, Loot (`fetch_item`), Shop (`buy`), Investigate (`read`, `say`), Break (`break_block`), Solve (`use_block`, `compose`), Gather (`gather_gems`), Travel (`travel`), Boss (`fight_boss`), Level (`enter_level`), Wait (`wait`) and Explore (`explore_area`). Each guard asks `my_op`: is the top op mine?
- **The safe default.** With no op, or when the op's executor has nothing to do this decision, Explore explores safe ground: off hazards, away from hostiles, and when hurt inside safe zones first. Once hurt-safe ground is all explored it pushes the boundary: the nearest frontier outside, still off hazards and away from hostiles, with the survival reflexes above it (live Walk run: "look around" took 18% of decisions with unexplored ground 150 blocks east). Only with no reachable frontier at all does it step to a safe neighbour. Hurt, with a known hostile within the planner's danger radius (6, `explore.CAUTION_RADIUS`), it explores nothing: it steps to the neighbour that gets furthest from it, safe-ish ground first, or holds when none gets further, only while that hostile is closing in (`survival.approaching`) and for at most 10 s, before it explores again (`explore.keep_away`; free-play run 6 started hurt beside a gristlewick and walked into it before the first plan landed; run 8 stood off one that kept its distance for 177 s, A82). A non-forced decision always has a productive intent. The only waits are forced ones (downed, asleep or unplaced, server-imposed) and the planner's `wait` op, which must say `why` and lasts at most 30 s.
- **Exactly one thing picks the movement target** at any moment: a reflex, the top op's executor, or the safe default. States never take turns moving the character, so the A58 runs 3–7 pacing pairs cannot form; the oscillation guard (A15) stays as a safety net that should not fire.
- **Commit to the target and the goal it serves (A71, `targets.py`).** A target, once picked, is kept until it is reached (or gone), proven impossible (no path at all, or stuck detection's give-up), or the op it serves changes; never because another candidate came nearer, and not when another state walked in between. A prerequisite (a key before a locked entrance) is a stop inserted before the target, which stays; a valuable in view worth the steps it adds to the way is a detour (A73), after which the walk resumes toward the same target. A new head op from the planner waits for the action under way to end. So no decision undoes the previous one without new information.
- **Stall clock.** An op whose executor makes no progress for 30 s is dropped and reported to the planner (`goal_failed`), so the stack never pins the agent.

## What the API gives today

| Call | Use |
|---|---|
| `POST /worlds/{code}/characters` `{name, avatar, model_agent}` | Create. 201 returns self. |
| `GET /characters/{id}/self` | Lives, health, perception range, movement speed, alive, placed. |
| `GET /characters/{id}/position` | `{map_id, x, y}`. 409 `not_on_map` until placed. |
| `GET /characters/{id}/world` | Tick rate, sandbox flag, status. |
| `GET /characters/{id}/terrain-tiles?map_id&x0&y0&width&height` | Block types inside perception, plus revealed ground, as a grid: `rows` of `legend` symbols, `?` for clouds. |
| `GET /characters/{id}/entity-tiles?…` | Characters, NPCs, supplies inside perception. |
| `GET /characters/{id}/zone?map_id&x&y` | Zone at a revealed cell: `safe`, `brightness`, and a hunting ground's `strength_ceiling`. |
| `GET /characters/{id}/minimap` | Every revealed map's size and level entrance marks (`entrances`: `{x, y}` per map). |
| `POST /characters/{id}/tick` `{"intents": [{...}], "snapshot_version": N}` | Replaces the character's queue with an ordered list (`[]` clears it; no `intents` leaves it running). Optional `snapshot_version` is the observation version last applied; the server answers with a delta when it still matches. Returns `queue_id`, `queue` while it is held, `finished_queue` once it ran to its end, `intent_results` since the last call (none for an applied `Wait`, B133), events by tick, dropped count, the observation, and the clock. |

Auth is `Authorization: Bearer <key>`.

A `Use` target `{"kind": "npc", "npc_id": N}` names the block that NPC stands on when the `Use` runs ([API rules § Use](https://agentrealm.gg/docs/api)). It ships in server release 1.11 (saims B126); **Fight**'s NPC swings depend on it (A45).

**One request per character per tick, with a burst of 3, on every character route.** Reads count. The limiter is a token bucket refilled on the front's tick interval ([Manual §7.4](https://agentrealm.gg/docs/manual#74-rate-limits)). So the agent runs a call budget: each tick it spends its call on the read it most needs or on the tick submit. The round trip carries the observation (B15). This agent reads ground chest contents and its own `health` / `max_health` from it; **Retreat** (A9) uses health with the threat table and directive params, and **Heal** (A10) uses it when hurt and out of combat. Each `Damaged` event also updates a threat table, after the same response's observation is applied: max damage per hit per hostile type, keyed by the source's type code, with an unmeasured default until something is measured (A6). A hit whose source is not among the entities perceived before or after that response, or has no type code, is not recorded. Trap and `occupy` damage is recorded under its own keys but never raises the default for an unmeasured hostile. **Fight** (A23) will add the full win estimate and margins. Terrain and entity reads still compete with intents for the same budget.

The runner paces one call per wall-clock window (`epoch / tick interval`). That is stricter than the bucket requires: safe, but slower than it could be.

## Real time

Worlds run at 10 ticks per second by default. The agent's shape already fits: the planner is the slow loop and writes plans off the tick, and the reflexes are the fast executor. The intent queue (B98) lets one request carry up to four seconds of intents, run one per tick; the agent sends movement as a paced `Step`/`Wait` queue, `Use` and `Say`/`Broadcast` through the attack and speech pacers, and most other intents as a one-intent queue (M6). A reflex that fires while a queue runs replaces it (see **Reflexes**). When a read or event makes the rest of a running path wrong, position is re-read and the next poll replaces the queue with a walk replanned from there, or with an empty queue when no route is left. Only a cell that became blocked after the queue was sent counts, so a blocker the plan could not avoid does not cost a resend every poll (A43). `run` does not send `Sleep` (B45) when it stops, so a stopped character stays standing until auto-sleep takes it off the map. See [Real-time play](https://agentrealm.gg/docs/guides/create-a-character-agent#real-time-play).

### Scheduler: which call this window

Checked top to bottom:

1. Position unknown, or a door or death may have moved us → read position. Not while off the map (A5, A58 run 9): after `Died`, or when the last self read says `placed: false`, position only answers 409 `not_on_map`. Poll `tick` instead, which still carries events; `Respawned` re-reads self, then position. While the last self read says alive but not placed, also re-read self every 10 windows, in case placement brings no event (`GetSelf` `placed`: GAME_NOTES.md Death, respawn, sleep).
2. Terrain around us is stale (map changed, or we moved more than half the perception range since the last terrain read) → read terrain.
3. Entities are older than the character's `entity_refresh` ticks, or a `Damaged`/`Attacked` event just arrived → read entities. A tick delta that carries entities counts as fresh, but once we have moved, a real read also comes due `entity_refresh` ticks after the last one: deltas alone let a walk run into hostiles it had not read (A16 Walk run 4, `WorldModel.entity_read_due`).
4. Otherwise → `POST tick` with the chosen intent, or with none, when the cadence below says it is due; else a pending `get_zone` on a revealed cell around a respawn anchor or along the path (A7), or send nothing this window.

`POST tick` runs on two cadences (M6). Urgent, meaning a hostile within 3 blocks, a `Damaged`/`Attacked` not yet re-read, or `Damaged` in the last round trip: every window. Calm: every 4–10 ticks, never later than the intents still queued run out. A paced movement queue opens the gap up to its length; a one-intent queue still brings the next poll a tick later. A window the gap skips sends nothing unless step 4 has a zone probe ready. The reads above outrank it, so a calm gap's spare windows go to stale terrain first, then stale entities, then safe-tile discovery. Each window counts as one tick, so a skipped window still brings the next poll and `entity_refresh` due.

Self is re-read after `Died`, and every 60 windows otherwise.

Movement goes as a paced `Step`, `Wait`×n, … queue along the path, cut at the world's horizon, with no trailing `Wait`s (M6). The waits per step are the ticks per move at `movement_speed`, rounded up. The next queue opens with the `Wait`s still owed since the last applied `Step`, counted to the latest tick a server response reported, not the windows counted locally since, so it never draws `movement_cooldown`. Position follows each `Step` result as it arrives, not the submit. A result counts only if it names the `queue_id` our own submit was answered with; a late result for an earlier queue is ignored, never adopted, even when the submit's response named no queue. An applied `Wait` has no result (B133), so results are never counted against the intents sent: progress is the highest result index and `queue.next_index`, and the queue is over only when a `finished_queue` names our `queue_id` or one of its results is rejected. A `finished_queue` naming any other queue is ignored. A lone intent (a `Take`, an unpaced `Use` or `Say`) is held the same way until its result or `finished_queue`, so it is never decided and sent again before it has run (A63 run 3: 20 of 22 `Take`s went twice). While that queue is still running, the window sends nothing unless a reflex below fires or a read or event makes the rest of the path wrong (`BlockChanged`, an entity on the path, a terrain read that disagrees, or a known hostile whose `hostile_range` now reaches a cell still to walk: A63 run 4, Heal walked a 10-`Step` queue into a known pack). Hostiles are counted, not cells (`brain.path_threats`). Three kinds never make a queue stale: the fight's group and the last hitter, which follow the walk anyway; any hostile the walk was planned without, which is every hostile for a losing Retreat (`Memory.path_skip`); and a hostile already in reach when the queue was sent, which the replan could not avoid. So a hostile moving while in reach is no new threat, and the queue is resent only for a hostile not yet counted. A cell already blocked when the queue was sent does not count either. In those cases the next poll replaces the queue with a replanned walk. The poll that looks for a firing reflex (`runner.reflex_while_held`) runs only the states that can answer with one (`dispatch.PROBE_STATES`: the reflexes but Greet, then Boss once a boss fight is engaged; in the park phase, `PARK_STATES`), never an executor's search, and when none fires the state that sent the queue stays the active one, so a poll stays quick while a queue runs (A64). The probe leaves no trace in memory: `Memory` is snapshot before it and put back whole when its answer is not sent (its corridor searches aside: they cache search work, not decisions, and copying them would cost more than the probe; `memory.SEARCH_CACHES`), so a pick, a try, a commitment or a re-arm made for an answer that never went out never happened (free-play run 5: probes counted Heal's drink tries for drinks never sent, and both potions were written off); a reflex that is sent keeps what it decided, but not the navigation learnings, stuck attempts, boss fight or Greet's tries (`runner.PROBE_NEVER_KEEPS`). The queue is dropped when a reflex fires (its intent replaces the queue, and since the dropped queue's later results are no longer read, position is re-read and the path forgotten), with two guards because a held `Step` may have run before its result came back: a reflex that walks to the very cell the held queue's next `Step` enters, or asks for exactly the intents the held queue has still to run (`Wait`s aside; A63 run 4: **Pickup** re-sent the held `Take`, 11 of 24 `Take`s wasted), leaves the queue running, and a replacement whose `Step`s, aimed from the tracked position, would land on a blocked, hazard or unknown cell from any cell the unconfirmed `Step`s could have reached in the ticks since the queue was sent sends a `Wait` instead and re-reads position (A63 run 3: a Flee step re-aimed from a stale position walked into known lava), when a `Step` is rejected (a rejection discards the rest server-side), when a death clears it, or when neither `queue` nor `finished_queue` has named it a couple of ticks past its length (the handoff store lost it; the character must not stall, and we may have walked unseen, so that drop also re-reads position and forgets the path and the last `Step` tick). A `Step` onto a door replaces the rest of the queue with `[]` on the very next call, before anything else is read, because the `Step`s behind it were planned from the wrong place. Once a rejection or a door has dropped the queue, a server `queue` echoed on that same response does not bring the hold back. A finished queue, a rejection, a door, a death, a firing reflex, or a lost queue send us back to step 1.

`Attacked`, `Damaged`, and `Died` on a queue are always ours: they carry no `subject_id` there.

### Reflexes: every round trip, no model

The first rule that matches picks the intent. They run on every `POST tick`, also while a movement queue is in flight: rules 2–4b drop that queue and send their intent in its place; rules 4c and 5 leave a live queue running.

1. Previous intent rejected → clear the path. A rejected `Step` teaches the map by its code (A14, `navigation/rejection.py`), every lesson keyed by map and cell:

   | Code | What the agent records |
   |---|---|
   | `not_traversable` | Impassable until a `BlockChanged` on that map and cell. |
   | `block_occupied` | Kept off for the next decision, then costs 100 extra for 30 ticks. |
   | `conflict_lost` | Nothing; the next move may retry. |
   | `door_locked` | Impassable, and stored as a locked door under the map's `doors` in the knowledge base, which every character of the world then keeps off. |
   | `over_strength_ceiling` | Impassable until the loadout (armed or worn) changes, and stored under the map's `hunting` in the knowledge base with the zone's ceiling for A27's strength bracket. |
   | `would_strand` | Treated as anything else below. The server refuses the move that would strand us (GAME_NOTES: unequipping the supply that keeps us on water), so the agent is never left stuck; it just tries something else next decision. |
   | anything else | Kept off for the next decision only. |
2. Standing on a block in `avoid_blocks` → step to the nearest safe neighbour.
3. Hostile in range: `on_hostile = "flee"` → the **Flee** state walks a committed multi-step escape: the best single step away first (standing still when cornered), then a route to a known safe tile or a run away from the hostiles (A9). `"fight"` → the **Fight** state (A23), not a reflex here.
4. `pickup = true` and a worthwhile supply underfoot, adjacent, or in a ground chest within reach → the **Pickup** reflex: `Take`, or `WithdrawFromChest` with that one `supply_id`. With the carried chest full, `Drop` the lowest-valued held supply first, only for a pickup worth more; otherwise skip it (A20). Walking to a supply further away is **Loot**'s, only for a plan `fetch_item` op.
4b. Our last death dropped a chest on this map, `pickup = true`, and a tile on or next to it is known safe (A7) → the **Recover** state (A11) walks there; on or next to it, `WithdrawFromChest` with only its `chest_id`, which takes everything that fits, until the snapshot shows it empty or gone. `Died` names the chest and where it landed; tick POSTs carry the last applied observation version when we have one, so most round trips get deltas and the chest's `contents` stay in the model without a full snapshot every time.
4b2. `pickup = true`, a walk under way, and a free gem, a life, or food while hurt in view, where going by it adds no more steps than it is worth: the walk over known ground from where the character stands to the find and on to the best cell of the route still ahead (the queued steps, then the path), less the steps the walk takes to that cell anyway (`detour.extra_steps`, `pathing.route_ahead`; free-play run 4 priced finds from the end of the queue and walked past gems beside the route). There is no fixed reach, but a find near in a straight line and far on foot (beside a later stretch of a route that winds round a wall) is left until the walk comes by it, so a detour stays a short insert; a gem pile is worth 8 steps and each gem pile next to it 4 more (up to 16), a life 16, food while hurt 4 (`detour.allowance`, A73: run 4 walked past a gem triple 5 cells off that cost about 7), on ground Gather may work (clear of every known hostile's bar, remembered hostiles included, A22) → the **Detour** reflex (A71) walks to it by a path that prices every known hostile's reach as costly and must stay clear of it (`gather_safe.route_clear`; a find with no such path is skipped for the run), Pickup takes it once in reach, and the walk resumes toward its committed target. A `gather_gems` op with `fight` on top lifts the remembered and route tests. A detour that has not taken its find in 100 ticks, or has no step, is given up and that find is skipped for the run; one whose ground or path turns out held (a hit on the way, say) is ended (free-play run 5).
4c. On safe ground, or off it while `policy.hostile` does not name NPCs, a likely helper in sight not yet spoken to, with no hostile hit in the last 30 ticks, no known hostile within 3 blocks, the speech cooldown done, and the top op not a `say` → the **Greet** reflex (A65): one `Say` "hello" to the nearest one. The API does not mark helpers (see **Server gaps**), so a likely helper is an NPC that has stood on one cell for 50 ticks in view (helpers stay put, GAME_NOTES NPCs; `WorldModel.npc_still`) and is not known hostile: a boss, the last hitter, or a type that has swung at us, hit us or died in view, this run or an earlier one (`survival.known_hostile`, the same test `is_hostile` applies to NPCs). A monster that has not hit us yet can pass that test only by standing still, and off safe ground no NPC is greeted while `policy.hostile` names NPCs, at any range. Greet never walks (`Say` reaches 25 blocks, further than sight). It fires only at a decision window: it is not a reflex for the runner's held-queue probe (`reflex_while_held`), which leaves its tries as they were, so a walk queue already running is never dropped for it, and it costs the walk one tick. An NPC is greeted once: the applied hello lands it in `greeted_npcs`, Greet's own record in the knowledge base; one whose result never comes back is retried after 30 ticks, at most 3 times. A hello never counts as speech for the planner's `say` ops: it does not enter `spoken_npcs`, a refused one spends none of a `say` op's 3 refusals, and a later `say` op to a greeted NPC still says its own text (the runner tags a `Say` as the hello when it submits one that Greet decided, `Decision.state`, never by its text, and files its result by that tag). An NPC already spoken to by a `say` op is not greeted.
5. Otherwise the top plan op's executor, or the safe default, picks the move (**Architecture: AI plans, state machine executes**); a path is walked as a paced `Step` queue (see **Scheduler**).

"Hostile" and "in range" read from settings: the API serves no hostile's reach and no other character's health.

### Plan: goal and path

A goal plus a path over the M7 cost grid (A12–A13, `navigation/planner.py`). Step costs: known walkable 1; fog 2, so unseen ground is assumed open and paths may run through it; fire and lava 1 plus their `occupy_damage` from terrain reads, or plus 100 when no read has named it; an NPC or character standing there plus 50 (high but finite: they move); a cell a `block_occupied` rejection named in the last 30 ticks plus 100; each hostile in `policy.hostile` plus 30 minus 5 per block of distance, out to 6 blocks. Known blocked tiles, void, tiles a rejection made impassable (reflex 1), and breakables are impassable except at break time (A28, below), and a door is entered only as the goal, since stepping onto one warps. A* runs over the known extent plus start and goal with a one-tile fog ring, so an unreachable goal returns no path instead of searching fog forever. It expands at most 400 cells per replan (A13); when it finds the goal or proves it unreachable, that is the plan. When the budget runs out first, the replan plans only inside the perception window, with the same budget: a goal in sight gets the path to it, or the best partial path toward it when the window does not connect. The cell the agent stands on competes on the same score, so a window where no reachable cell beats it is no path: a dead end beside a goal that cannot be reached is reported as stuck, never a step away and back (A58 run 7). A goal out of sight also gets a coarse corridor search over 16×16 cache tiles, at most 48 tiles expanded per replan. It runs backward from the goal and is kept per plan (`goto` on its own map, the death chest) in `Memory.corridors` across replans until the goal or map changes or a step is rejected, so each replan carries on where the last stopped. A cache tile costs 16 times its mean passable step over the passable share, priced by the same grid (fog, known blocks, hazards, avoided, rejected and costly cells, occupants, hostiles); a finished corridor is re-priced every replan and searched again when a tile on it got dearer or impassable. The window search keeps to the corridor's tiles and those beside them, and ends on the cell with the best cost so far plus twice the estimated distance left along the corridor search's tree (from a cell, to the next tile toward the goal in that tree, its centre or the goal itself in the goal's tile, then along the tree), which is the same whatever tile we stand in; a corridor that gives no cell better than where we stand is no path, which stuck detection escalates, never a straight-line retry (free-play run 4, `planner._toward`); until the corridor is finished it heads straight for the goal. The executor walks the known prefix and replans when it runs out. `explore`, `doors`, and the door-graph floods of a cross-map `goto` (A26) pick among known tiles with the unbudgeted search of A12. Picking the nearest of many targets (`nearest_target`) is one Dijkstra from where we stand that stops at the cheapest target (ties go to the one nearer in a straight line, then the smaller cell), then one A* for its path; so unreachable targets cost at most one flood between them, not one each. Each search prices a cell once, and hostile danger is laid out once per search instead of summed per cell, and the map's frontier is kept up to date as tiles change instead of found afresh each ask. On a 30k-cell map a whole-map explore decision takes well under 100 ms (A23 Run 2 blocked 5–17 s; `tests/test_navigation_speed.py` guards it). The next step must be a seen walkable or door tile, and the queued walk stops before the first cell that is occupied or otherwise not open now, so it never Steps onto an NPC the grid priced at 50. A path whose first step is on an unseen tile does not count; the op's executor has no step this decision and the safe default moves. `avoid_blocks` are impassable except when standing on one with no safe step off: then they cost 100 extra per step, so the plan crosses as few as it can. Movement is Chebyshev: diagonals cost the same as straight steps.

`policy.goals` are input to the built-in planner, which turns each into one op; no state reads them.

| Goal | Op | Target |
|---|---|---|
| `explore` | `explore_area` anywhere | Nearest frontier: a known walkable tile next to an unknown one. |
| `doors` | `travel` to `entrance` at `0, 0` | Nearest known door (`framed_door`, `rock_entry`) whose warp is not yet recorded, else the nearest door. Stepping onto one warps. |
| `goto` | `travel` to `point` | A fixed `(x, y)`, on `policy.goto_map` when set (A26), else the current map. A goto already stood on gets no op (A16). |

Re-plan when a step is rejected, when the map changes, or when a terrain read disagrees with the path.

**Door graph (A26, `navigation/door_graph.py`).** A `goto` on another map, or one not reachable on this map, is a Dijkstra search over the door graph: nodes are the start, the goal, every known door and every warp landing; walking edges come from one cost-grid flood per node, and a door with a recorded warp has a zero-cost edge to its landing. A door reached on foot is left only through its warp, so one whose warp is unknown is a dead end; the start walks out even when it stands on a door. The agent walks the first leg; after the warp, it replans from the landing. With no known route the goal yields like any unreachable one. Warps are learned by observation: a `Step` onto a door sets `warp_from`, and the next position read records where it landed, unless it still stands on the door (no self-loops). A refused Step, a death, or a not-on-map error drops the pending warp. Knowledge base shape, under `maps["<map_id>"]` (`knowledge_maps.py`): `terrain` is `{"x,y": block_type}`, merged per terrain read's window and once more from the world model at exit; `doors` is a list of `{x, y, block_type}` sorted by cell, plus `to_map_id`, `to_x`, `to_y` once a warp is recorded, and `locked: true` once a Step onto it was refused `door_locked` (A14).

**Stuck detection (A15, `navigation/stuck.py`).** Every path to a target on the current map is an attempt keyed by goal, map and target cell; Explore (the plan's `explore_area` op and the safe default's `explore`), Travel (`travel:<to>`, every plan `travel` op, including the built-in planner's `goto` and `doors`), Recover (the death chest) and Level (`level:door`, `level:frontier`) all run through it. So do the short walks to something in sight, Heal to food or a safe tile (`heal_food`, `heal_rest`, `heal_measure`, `heal_town`) and Loot to a pickup (`loot`), through `pathing.bounded_step`; those skip the ladder below and go straight to step 5 on no path or the first failed window, since nothing in sight is worth a broken block or a reveal walk. The one exception is food within Heal's reach with no walk to it but a block on the straight way there that something held opens (a bush and a blade): Heal opens it Break's way before walking (`states/heal.py` `_cut_toward`, A16 Walk run 4). Making an attempt active restarts its time window, since only time spent pursuing it counts; so only a walk that sends a step makes its attempt active, and one whose first step is taken or unseen waits without touching the active walk's window. It is given up after 300 ticks of waiting with no step in between, timed from when the wait began. A bounded walk's progress window and its wait both hold only while the walk is pursued (tried, step or not) on consecutive decisions, counted by dispatch (`NavStuckMemory.decision`); a walk that was not pursued on the previous decision (Heal left it on health back, food eaten on the way, or a higher state's turn) starts both afresh when it is taken up again (`nav_stuck.resume`). So a food or pickup is never given up on time it was not being walked to or waited on, and an owed goto held below Heal or Loot still escalates. A Heal or Loot walk's attempt is also finished when its food or pickup is in reach to `Take`. A give-up drops the current path only when it is the given-up attempt's own. These give-ups queue a `stuck` signal like any other, on purpose: the trace and the M7 gate report give-ups on other goals from them, and a strategist that sees food or a pickup it cannot reach can plan around it. They cannot flood the 16 kept signals, since each target backs off for 300 ticks, doubling on each give-up. Progress is the remaining length of the planned path plus the straight-line rest to the target, read when the state plans or keeps a path; an applied Step only bumps counters, so no search runs per move. The attempt is stuck when that measure has not fallen in 20 applied moves or 300 ticks, when its last 8 cells hold 3 or fewer distinct ones, when 3 of its Steps in a row were rejected (an applied Step resets the run; another goal's Steps do not count), or when the planner finds no path. A route whose first step is taken by an occupant is not "no path": the attempt sends nothing and waits out its window. Escalation follows PLAYABLE_AGENT_PLAN Navigation §4, each level with a fresh window and entered only when the one before failed: step 1 replans with fog at 8 instead of 2 (one that finds no path fails at once); step 2 (**Break**, A28) arms a held capability and `Use`s the first breakable on the straight route to the target when break memory has no failed `(block, capability)` pair for it (an `applied_no_effect`, or a refused `Arm` or `Use` other than `attack_cooldown`, marks the pair failed; with no pair left, step 3 starts); Recover and Investigate walks at step 2 yield the round so dispatch reaches Break; step 3 walks up to 40 moves toward the reachable frontier cell nearest the target, found by a breadth-first search over at most 400 seen open cells, which keeps the route along the obstacle (it stands in for the spec's left-hand wall follow and cannot circle); a plan shorter than any seen before ends the reveal and is walked, and failing again tries step 4; step 4 replans only through the door graph (`alt_route_path`, A26/A28), not another same-map A* to the same cell; a break that opens its block, or a step-4 route, walks again from step 0 on probation (`stuck.walk_again`): if that walk fails before standing 5 cells (`RESET_PROGRESS_CELLS`) nearer the target than the attempt ever had, the ladder resumes after the level that reset it, so grass cut beside a route that fails the same way cannot loop the ladder and the target is still given up (A16 Walk run 3); step 5 backs the target off for 300 ticks doubled on each give-up, drops its path, and appends a `stuck` signal (goal, reason it first got stuck, why each level failed, explored outline, blocking block types) to `Memory.nav_stuck.stuck_signals`, which keeps the last 16; the strategist (A35) drains them as its `stuck` trigger. A given-up frontier cell is skipped by `explore`, `explore_area`, Level and Heal's zone walk (`heal_explore`): every walk to a frontier cell is registered as `frontier` in `nav_stuck.SHARED_KEYS`, so a cell one gives up on is skipped by all, and a given-up door by `doors` and Level, until its backoff ends; a given-up door, Travel destination or chest yields the round, and the safe default moves. Break attempts live on `KnowledgeBase.breaks` keyed `"<map_id>,<x>,<y>,<capability>"`; only at step 2, or while **Break** walks to the cell it opens, are the breakables on the straight route to the target passable in the cost grid, at weapon cooldown plus one, plus the tool's gem price when the Supplies reference does not list the supply as kept on a break (`used_up_on_break` false: swords, knives, mallets); after a break opens its block, Break re-arms the weapon armed before it (A28). A supply's capabilities come only from the Manual's Supplies reference (A54) or from a break that subtype already opened (A46); only held or armed supplies count, since worn gear cannot be armed. **Escape** never breaks blocks; it only steps off hazards. Plan op `break_block` is handled by **Break** (A28). A cross-map `goto`, Travel or plan `travel` op tracks the first leg toward the door on the current map the same way, backing off the ultimate destination on give-up; after the warp it tracks the destination on that map. A cross-map destination with no known route yields without backoff: no route is not stuck.

### Planner: sets goals and settings

- **scripted**: goals and settings come straight from the character file.
- **llm** (M4, superseded by the strategist in [`docs/PLAYABLE_AGENT_PLAN.md`](docs/PLAYABLE_AGENT_PLAN.md), shipped as `strategist.py`, A35): the AI planner, on in every live run. On every event (op done or dropped, stuck, death, hurt, new clue, new map, a discovery, A71, A72) and, with no event, 15 s after the last reply (A83) it sends the model a summary of the world model and gets back the goal stack and settings, within a per-minute budget. It runs off the tick loop. The loop keeps the old answer until a new one lands, so a slow model never costs a tick. `run --no-planner` falls back to **scripted** goals from the character file, as a test mode.

## Character file

One TOML file per **behavior profile** (`python/characters/<profile>.toml`). The file stem is the profile name. `tomllib` is in the standard library. Name, avatar and model agent belong on `create`, not in the profile (A59).

```toml
world = "sandbox"

[policy]
kind = "scripted"                   # idle | wander | scripted (the AI planner, A35, sets the goal stack on top)
goals = ["explore", "doors"]
on_hostile = "flee"                 # flee | fight | ignore
hostile = ["npc"]                   # npc, character; an NPC counts once its type shows hostile (A9)
hostile_range = 2
pickup = true
avoid_blocks = ["fire", "lava"]
entity_refresh = 5                  # ticks between entity reads when calm
```

At run time, pass `--character-id` / `AGENTREALM_CHARACTER_ID`, or `--character-name` to pick an existing character in the profile's world. Each run appends a JSONL trace at `python/.state/<profile>.<character_id>.trace.jsonl` (gitignored).

A separate runtime file, `characters/<profile>.directives.toml`, is re-read whenever it changes (A8). It carries survival `params` (defaults and ranges in [`docs/PLAYABLE_AGENT_PLAN.md`](docs/PLAYABLE_AGENT_PLAN.md)), a hard `never_attack` list enforced in the reflexes and on tick submit, and optional strategist fields (`goals`, `instructions`). On reload, changed `goals` rebuild the goal stack from the top and drop the current path, so the new top op replans at once; unchanged goals keep the stack's progress and the current path, and only reset its params to the file's values. Path ownership follows the plan head: **Explore** keeps walking a path only while it was set for the stack's current top op (same op and target), so a head change, even to another op of the same kind such as a second `travel` point, replans. With no valid `goals`, the AI planner fills the stack (A35); only in the `--no-planner` test mode does the built-in plan mirror `policy.goals` one for one (A34, `plan.py`). A `goals` list where every entry is invalid logs that and is treated as no `goals`. An op no state runs (`hunt`, `avoid`) is dropped with a log line when it reaches the top of the stack, and an op whose executor makes no progress for 30 seconds is dropped too (a `travel` to a `hunting_ground` with none known searches for one instead, bounded, A27); meanwhile `policy.goals` get the move, and a path one of them sets is kept until it goes stale instead of being replanned every window. A `travel` op of any `to` that resolves to a cell stuck detection gave up on (`entrance` at `0, 0` aside) leaves the stack for good and is unpinned (A16). Directives `travel:*` entries are not stack ops: **Travel** (A27) reads them straight from `goals` and keeps its own queue, so the stack's `travel` ops come only from the built-in plan or the strategist. **Gather** (A22) reads a `gather_gems` goal straight from directives `goals`, so dropping it from the stack does not stop it. `wait` seconds are converted at the world's `tick_rate_hz`. `never_attack` and the survival `params` **Retreat** reads (`retreat_hits`, `risk`, `lives_floor`, A9) change behavior today; `fight_margin` feeds only the win estimate **Fight** (A23) will gate on. The states read the plan's params (`Plan.params`): the file's values, tightened by a stack `set_param` op or by the strategist (A35) within the param limits; a reload resets them to the file's values. A file that fails to read or parse keeps the last good directives, or the defaults on first load; deleting the file restores the defaults.

## CLI

```
python -m agentrealm_agent create characters/wren.toml [--name Pat --avatar default --model-agent agentrealm-reference/scripted]
python -m agentrealm_agent run characters/wren.toml --character-id ID [--park-seconds 60]
python -m agentrealm_agent status characters/wren.toml --character-name Pat
python -m agentrealm_agent metrics characters/wren.toml --character-id ID
python -m agentrealm_agent metrics path/to/wren.42.trace.jsonl
python -m agentrealm_agent compare-metrics baseline.trace.jsonl candidate.trace.jsonl
```

Environment: `AGENTREALM_API_KEY` (from the account page on agentrealm.gg), optional `AGENTREALM_CHARACTER_ID` (used only when neither `--character-id` nor `--character-name` is passed), and `AGENTREALM_BASE_URL` (default `https://api.agentrealm.gg`, the public API; lives there are permanent).

One profile per invocation; several characters means several commands. `create` prints the new character id and writes no local file. `run` drives one character until interrupted (Ctrl-C or SIGTERM), then parks it on safe ground for up to `--park-seconds` (default 60; 0 = off) and clears its intent queue before it exits (A66); a second signal stops the park and exits within 5 s, clearing the queue only if that call finishes in time. It logs one line per window to stdout (tick, position, call made, intent, the result of the last one, events) and a JSONL trace to `.state/<profile>.<character_id>.trace.jsonl`, so a death can be read back as a decision. `metrics` takes a profile (`.toml`, any case) plus `--character-id` (or `AGENTREALM_CHARACTER_ID`) to build the keyed path, or any other path as a trace or metrics snapshot, and reads the last run from that trace (the trace is appended to; each run starts with a `world` record) and prints levels cleared, deaths, kills, gems, time per level, and how many lines it could not parse. Time per level runs from leaving the overworld (the town's map) to the level's `level_clear_ceremony`, across every map of the level; a run that starts inside a level has no time for it (A41). `compare-metrics` subtracts a baseline from a candidate and prints the deltas, so a regression shows up as a number (A42). Each side is a trace (`.jsonl`) or a metrics snapshot (`.json`). A delta is `null` when either side has no value: `gems` never seen, or a level timed in only one run (cleared in one and not the other, or entered mid-level), which would otherwise read as a slowdown or speedup of the whole level time.

## Tests

Standard library `unittest`, no server. They cover what the agent decides, not the wire: pathing, frontier choice, reflex order, and the scheduler's choice of call. `tests/test_starter_agent.py` covers the starter agent (A52) the same way: its call choice, Sync/Flee/Explore order, pathing around walls, resync, error handling, and the `create`/`run` commands. Run with `python -m unittest` from `python`. The suite runs against a temp state dir (`AGENTREALM_STATE_DIR`, set in `tests/__init__.py`) and fails if any test opened, wrote or removed anything under `python/.state` (A86).
