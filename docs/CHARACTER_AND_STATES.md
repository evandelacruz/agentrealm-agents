# Character files and state behavior

This page holds the per-policy and per-state detail for the reference agent. For architecture and backlog, see [`PLAN.md`](../PLAN.md). For a short overview, see [`README.md`](../README.md).

## Quick start details

`create` prints a new character id (A59); nothing is written under `python/.state/` for that. `run` drives one character until Ctrl-C or SIGTERM, then parks it on safe ground for up to `--park-seconds` and clears its queue (A66; README **Stopping a run**): one line per window to stdout and a JSONL trace at `python/.state/<profile>.<character_id>.trace.jsonl`. Pass `--character-id` or `--character-name`, or set `AGENTREALM_CHARACTER_ID`; a flag overrides the environment. `metrics` takes a trace path, or a profile plus `--character-id`, and summarizes the last run in that trace (deaths, kills, gems, levels cleared, time per level; PLAN.md A41); the trace keeps every run, and each starts at its `world` record. To compare two runs or two commits, keep trace paths or metrics JSON snapshots and run `compare-metrics`; it prints candidate-minus-baseline deltas (PLAN.md A42). A positive `deaths` delta means the candidate died more; a positive `time_per_level` delta means it took longer on a level both runs cleared. A level cleared in only one run has a `null` delta, as does `gems` when either run never saw a value.

Characters in the same world share one learned knowledge file at `python/.state/worlds/<world_code>.json` (gitignored): `run` loads it once at start, refusing to start if it is unreadable, and saves it once at exit. Its `items` section holds, per `supply_subtype_code`, weapon reach from a `target_out_of_range` rejection, shop prices seen, and `weapon_damage`: per `npc_type_code`, the largest single hit we have seen this weapon land on that NPC type, counted only when the hit can only be ours. Damage is rolled and depends on the target's defense, so it is a lower bound on the weapon's best hit against that type, not the weapon's damage stat (PLAN.md A18). Its `entrances` section holds one row per minimap entrance mark, keyed `"<map_id>:<x>,<y>"`, with what a look found there (`looked`, `block_type`, `locked`, `needs`); a file from before map-keyed rows is rekeyed once at load (PLAN.md A30).

For worn armor, `items` also holds, per `npc_type_code`, `damage_taken` (the largest hit taken with that item as the only worn piece) and `damage_without` (the largest hit taken with nothing worn, after our `Remove` took that item off, until the next loadout change, death or map change). `damage_saved` is their difference, recomputed whenever either changes. Hits in a response where the worn loadout changed are not counted (PLAN.md A18).

Run one `run` process per world at a time; two would each save their own copy, and the last to exit wins. Stopping the agent leaves the characters in the world where they stand. The game runs at 10 ticks per second; PLAN.md **Real time** says how the agent keeps up.

## Make a character

**Some behavior runs only for plan ops the planner emits** (A61, A35): equipping gear (`equip`) and restocking potions (`buy`), which M8 checks; reading signs and greeting NPCs (`read`, `say`), which M10 checks; and walking to look at entrance marks (`travel`), which M9 checks. With `--no-planner` nothing emits them. `buy:<code>` and `travel:*` can go in directives `goals` by hand (a `buy` buys one more of its item, whatever is already held); `equip`, `read` and `say` have no shorthand and wait for the strategist.

Copy a file from `python/characters/` and edit it. Names must be unique in the world.

**Oscillation guard** (A15, A58, A90). A safety net: with one state picking the movement target at a time (A61) it should not fire. Two states could take turns moving the character: one steps it east, the next decision another steps it back, and it paces between two cells. Each state on its own sent a sensible step, so no state can see this. Dispatch checks for it once per decision, before any state runs (`navigation/oscillation.py`): when the character stood on at most 2 distinct cells over its last 6 cell changes (standing still is not counted), it gives up every walk that made one of the pacing moves, whichever state sent it and whichever stuck attempt was active, through stuck detection's step 5 (a backoff of 300 ticks doubling on each give-up of that target, a `stuck` signal with reason `pacing` and `retry_at_tick`), writes an `oscillation` event to the trace, and lets dispatch pick again. After each decision dispatch notes which walk the move belonged to (the goal of `Memory.path` when the step lands on its next cell) and the target that walk heads for (`oscillation.walk_key`: the active stuck attempt's when it is that walk's, else the walk's committed target, else where its path ends), so every walk is known by its target, not by who sent it. A walk to a block is a walk like any other: its block is given up, no stuck ladder, cost grid or Heal walk nominates it while the backoff holds (`break_memory.given_up_blocks`), a planner `break_block` for it is dropped with the reason, and a stuck walk whose step 2 nominated it leaves step 2 for the reveal. It does not matter which states caused the pacing, so a new state needs no special case for it. A step that lands on no path is no walk and gives nothing up, so Fight pacing with steps of its own never backs off a goto or explore target left over from earlier; the trace still records the event and which states moved. When the plan's top op's executor made such a step, the op stalls (A104). When only Flee and Retreat did the pacing, nothing is given up: the event carries `escape: true` and the guard hands them the paced cells: on that same decision Flee plans a fresh escape that keeps off them, or Retreat routes around them; the next decision drops them either way. This is separate from the per-attempt oscillation check in stuck detection, which only sees one goal's own steps and escalates a level.

Each profile may also have `python/characters/<profile>.directives.toml` beside it. The runner re-reads it when the file changes; a file that fails to read or parse keeps the last good directives (defaults if none loaded yet); deleting the file restores the defaults. `never_attack` lists kinds or NPC type codes the agent must not swing at (`character`, or an NPC `code`); a fight reflex that would `Use` a forbidden target flees instead, and any other `Use` aimed at one is replaced by a `Wait`. A `Use` on the character itself (**Heal** eating or drinking) is not an attack and always passes. `params` tune survival: `retreat_hits`, `risk`, and `lives_floor` set when **Retreat** fires from health and the threat table; `fight_margin` scales the win estimate **Fight** and **Flee** gate on (A23). The win estimate weighs ticks for the hostiles to kill us against ticks for us to kill them, both sides' swings priced by the published roll: ours at the world's base attack power of 2 (a hit 65% of the time, for 1 up to 2 plus the armed weapon's damage; the pocket knife 1–4), one swing per the armed weapon's attack cooldown (the knife every 0.8 s, a mallet every 1.3 s; A123), a measured hostile's with its largest hit as its attack power and its measured hit rate, and a type never measured at the base attack power of 2 (A81, A85). At the default margin the knife takes one weak hostile, measured or not, at full health and refuses a pair or a type measured to hit hard. `curiosity` is kept for the strategist; no state reads it (A61). Out-of-range param values are ignored.

`goals`, when set, are manual steering: they go on top of the plan stack and outrank the strategist, which plans below them; once each is done or dropped, the strategist owns the stack. A program can add goals on top of the file's without writing it (`CharacterConfig.pinned_goals`; the M7 smoke pins its target this way); each is pinned once, so after its op is done or given up a reload never brings it back. A `travel` op of any `to` (point, town, shop, hunting ground, an entrance with a cell; not an `entrance` at `0, 0`, the nearest unexplored door) whose destination resolves to a cell stuck detection gave up on leaves the stack for good, pinned or the planner's; the planner's prompt lists those cells, and a reply that sends a travel there again is filtered out (A16). The planner sees the stack with each op marked `pinned` or `planner`, and is told it cannot remove pinned ops, only plan below them (A35). Shorthand `gather_gems:20`, `buy:bronze_mail` and `travel:<to>[:[map_id:]x:y]` (`town`, `hunting_ground`, `shop`, `entrance`, `point`) become typed plan operations validated against the strategist op table (A34). A reload with the same `goals` keeps the stack's progress and the current path; changed `goals` restart the stack and drop the current path and every committed walk (A15). With no valid `goals` (none set, or every entry invalid, which is logged), the built-in planner builds the stack from `policy.goals`. Each op runs only in its executor (see `policy.kind`); finished ops pop, ops no state carries out (`hunt`, `avoid`) are dropped with a log line, and an op whose executor makes no progress for 30 seconds is dropped too, while the safe default moves. A `travel` to a shop or entrance with `x = 0, y = 0` means the nearest known one; `travel:town` and `travel:hunting_ground` take no cell; a destination the knowledge base cannot place yet sends nothing and stalls, except a `hunting_ground`, which explores while spare windows read zones for one, until it finds one, the frontier runs out, or 300 s pass (A27). A plan `travel` op needs `x`, `y` only for a `point`. Hunting grounds closed by `over_strength_ceiling` reopen when the loadout changes (PLAN.md A27). **Gather** (`gather_gems`, A22, A88) waits for a snapshot to report the gem counter, then runs one search for the place to work: grass to cut (never a bush: bushes drop berries, not gems, A81), free gem piles to take (`gem` in Olympuff; GAME_NOTES.md), and the edge of unexplored ground, where more grass may lie. Every one lies on known ground off hazards, with no known hostile near: within 6 blocks of the one that hit us, within a step past weapon reach or `hostile_range` of any other (the survival states keep it alive in the field). Hostiles out of view count too: it remembers where each was last seen (for 600 ticks), the post a guard stands on, and how far from that post one has hit the character, keeps off that ground, and no walk crosses a known hostile's reach (the search treats it as a wall), so a hit on the way to a pile drops that pile; a `gather_gems` with `fight: true` gathers there anyway (Detour obeys the same tests). A hostile that stays near without attacking only bars the cells near it, so Gather works further off; fighting it is the Fight reflex's call or the planner's (`fight`). Each place is priced the same way: its walk (steps, plus steps for ground near a known hostile), then the work there for the gems still needed at the yield there (a cut for each gem a cut is expected to drop, at the region's measured yield or the map's `expected_yield` on ground not sampled yet; a pile is one `Take` for a sure gem, then cuts for the rest; an edge first pays the steps it takes to find grass past it), and the cheapest wins (A105). What is in reach (a pile beside it, the grass it stands on) costs no walk, so it is worked unless the walk Gather would take costs less in all. A cut goes out with a held tool that cuts, armed first when the armed item is not known to cut, and the weapon it swapped out is armed again once no `gather_gems` op is on top. Safe-zone grass is cut like any other until its cuts show otherwise: it skips cells it cut too recently to have grown back (600 ticks) or whose last `Use` had no effect (held out 600 ticks, never filed as a cut), and after 3 no-effect cuts in one region or one safe zone (Break's capability probes, and cuts made with an item known not to cut such as a potion, do not count) it treats that whole region or zone as uncuttable for a while; town grass did not cut (GAME_NOTES.md), which is what this learns. With nowhere to go it explores for one. It leaves grass alone in a region its own cuts showed barren (16×16 blocks with no gem after 15 cuts, which ground at the manual's 20% would almost surely have broken; A63, A81) unless the op names that region with optional `x, y` (`gather_gems` with `count, x, y`); every cut and whether a gem came of it is kept per map in the world knowledge base, and the planner's State shows the map's measured yield (`expected_yield`), the best regions at any distance (with `distance` in blocks) and the barren ones nearby as `gem_yield`, plus Gather's last decision as `gather_status` (`cutting`, `taking a gem`, `walking to grass`, `walking to a gem pile`, `walking to unexplored ground`, `walking to a target region`, `blocked by hostile`, `cuts have no effect here`, `no cuttable cell in view`, `region barren`; any but `cutting` ends in `, no cut for N s` after 30 s with no cut, and ` (region x,y)` while Gather works only in a target region) and this run's `gather_run` (`cuts`, `no_effect_cuts`, `gems_gained`, plus the current gather's `gems_per_min` over `gather_minutes` once a `gather_gems` has been on top for 60 s; any other op on top ends that gather, and its rate stays shown until the next one starts, A121). That `x, y` names a target region, the planner's choice: Gather goes only for places there (grass, piles, unexplored edges) while it knows one there, walks toward the region while it knows no cell of it, and works as if none were named once it knows nothing there or no way reaches it; it lifts that region's barren mark. **Solve** handles `compose` once every fragment is held (one per slot), and `use_block` by arming the named supply in hand and `Use` on the block (walking into reach first); `use_block` is done once the target's block type changes, and then Solve re-arms what was armed before (once, if still in hand). Only a step counts as progress for Solve and Break, so a `Compose` or `Use` that changes nothing cannot pin the stack. **Investigate** walks into reach and sends the op's `Read` or `Say`; the knowledge file remembers reads and speech, and an op refused 3 times is finished. A `say` names its NPC by `npc_id` or `npc_type` (the nearest of that type in sight). The planner's State lists the nearest 5 NPCs in sight as `nearby_npcs` (id, type, distance and direction, whether a `say` op spoke to it, whether Greet greeted it, whether known hostile, whether it stays put), `npcs_spoken_to` and `npcs_greeted`, and a helper's reply reaches it as an `npc` clue (A65). **Level** walks to the `enter_level` entrance, then toward the level's unexplored doors (then frontier tiles), and finishes the op when no step is left. **Equip** applies the best upgrade each decision until none is left. `wait` needs `why` and at most 30 seconds, counted at the world's tick rate. `instructions` are kept for the strategist (A35).

In a calm window it would otherwise skip, the agent calls `get_zone` on one revealed cell: first within 8 blocks of town or its last respawn point, then, while **Travel** searches for a hunting ground none is known for, one cell in every 4 × 4 square of its view (A27), then on the cells of its planned path. A terrain read's `safe` flag already marks safe-zone cells, so those are known safe without a zone read and never probed; their brightness is then never read and counts as 1. It records which are safe for retreat (A9) and death-chest recovery (A11). When hurt and out of combat, **Heal** walks to or takes food lying within 3 cells, else (out of combat only) cuts a bush within 3 cells a held blade cuts and takes its berries (A135), then `Arm` + `Use` self (target `{"kind": "self"}`) on a potion, only by the one potion rule (never at full health; food is eaten on pickup and never carried, so food is taken only once hurt by at least its heal, `healing.worth_eating`, A155; `healing.spend_potion`, A96, A135): in combat or about to be (under attack, a hostile in range, a boss fight, inside a level, or a fight op next) when health is low (at or below half of max) or the win estimate says the drink turns the fight, and then before any walk for food; out of combat only at that low line once no food near can be had, so a potion held is a reserve for fights and levels (Retreat losing ground and Flee cornered drink by the same rule, and the planner's `use_item` of a potion the rule refuses is dropped with why), both in one paced queue; on its next decision it re-`Arm`s a weapon, before anything else: the one the drink swapped out, else the last one armed this run, never a potion or tool (once, even if health is already full or a hostile is in range). Health rises only from potions and food, never by resting (A130), so Heal never walks to safe ground to wait; safe ground is the refuge **Retreat** and **Flee** run to from attack. A food `Take` or a drink the server rejects is handled by the rejection's code, with no try cap (A80): nothing armed, arm it and drink again; the supply gone or not carried, forget it; a `Take` out of reach, walk onto the food first; dead or on a cooldown, try again a weapon cooldown (1 s) later; anything else, an unknown code included (traced as `heal_refusal`), not again until where it stands, what it holds or arms, its max health, or the food's cell changes (health alone moves too often to count). A drink whose `Use` applied but left the supply carried, with no `SupplyUsed` of ours for it and no health back, drank nothing, and the next decision reads why (A76, traced as `heal_noop`): something else in the armed slot, arm it and drink again (or, if that drink already sent its `Arm`, hold it); full health, not again until health is below that reading; armed, hurt and nothing changed, not again until the map, the supply ids it carries or its max health change, or health falls below that reading, so a potion is never unusable while health falls. The armed supply is read by id from the snapshot's `inventory.armed`: a drink of a potion while another of the same code is armed sends its `Arm` first, and a potion left armed is still drunk even if `held` leaves it out. Only server rejections are filed, from any state (Pickup's refused food `Take` and Retreat's drink included), never a drink decided while a queue was held and not sent (free-play run 5). With nothing to eat and no potion due, Heal asks the planner once for food and potions (a `heal_supplies` trigger, raised again only after a full heal, carrying the potions held back as that reserve) and sends nothing, so the plan's executor or the safe default moves. How much each food and potion heals is the Supplies reference's; nothing is learned from health changes (A155). Each walk to food, and each **Loot** walk to a pickup, gives its target up (backoff 300 ticks, doubling) when there is no route or the remaining path has not shortened in 20 moves or 30 s, or it paces; the next food or carried supply is tried instead (`pathing.bounded_step`, A15). A walk whose first step is taken or unseen waits, and is given up after 30 s of waiting, timed from when the wait began. A walk's 30 s clocks run only while it is pursued decision after decision: one Heal or Loot left and later takes up again starts them afresh, and its record is cleared once its food or pickup is in reach to take.

Every chest our deaths dropped is remembered, across runs, until it is seen empty or gone (A122); the planner sees each in State `death_chests` and goes back for one with a `travel` to its cell. With `policy.pickup` on, **Recover** withdraws from any remembered death chest in reach, wherever it lies, unless nothing in it fits the pack, and walks back as a reflex only to one on this map with a known safe tile on or next to it: the newest anywhere on the map, an older one once in view. Until then, or while no step toward it can be planned, it sends nothing and the next state moves. At the chest it withdraws everything when it all fits, else the best supplies by id that fit; with a full pack it drops nothing (what to give up is the planner's call, A102) and skips a withdraw that would only repeat `carry_capacity_full`. Only that tile is checked, not the route to it. **Escape**, **Retreat**, **Fight**, **Flee** and **Pickup** outrank it. Urgent windows and the `idle` policy never read zones.

**Remembered hostiles let go on evidence, and measured types are kept** (A85, free-play run 9, A162). A hostile keeps no post (Manual §11 Hostiles): it goes for the nearest character on its map and stands still only where the ground stops it, so one seen standing still away from it, with no step that would close in, is blocked, not guarding (`Sighting.still`, `WorldModel.blocked`, after `world.STILL_TICKS` in view; one standing still beside it is swinging, not blocked). Out of view it holds its bar round the cell it was last seen on: a moving one for a minute (`SIGHTING_TICKS`), a blocked one for 5 minutes (`BLOCKED_SIGHTING_TICKS`), since the ground or the nearest character may change unseen; either is forgotten once that cell is in sight with it gone (A95: looking is the evidence). Where it was last seen and whether it was blocked are saved, so the next run starts from them; a row an older agent saved with a post loads at its last-seen cell, not blocked. The damage each hostile has taken is kept until it dies (`WorldModel.npc_damage`, this run only), and the win estimate prices the health it has left (`survival.health_left`). The threat table is saved too, per NPC type in the knowledge base's `npc_types`: the largest hit it dealt us and its swings that hit and missed. The win estimate prices a type's swing on its measured hit rate (the published roll counting as 10 swings) at its largest hit, and a type never measured at the world's base attack power, 2; it is no longer refused for being unmeasured.

**Equip** (A19, A55) runs for a plan `equip` op, and acts when something in hand clearly beats the weapon or armor already in that slot, or when something in hand that may be worn has no known worn slot yet: it `Arm`s a better weapon, `Remove`s a worn piece and `Wear`s the upgrade, or tries a single `Wear` on a held subtype whose slot neither a snapshot nor the Supplies reference gives (priced or not) so the next snapshot's `worn` teaches the slot. A subtype the reference lists as a tool, consumable or gem is never worn, so matches or a torch are never tried on (A95). It arms only the Supplies reference's `weapon` class (A54), and never while Heal, Solve or Break is using the armed slot; otherwise a potion or tool left there counts as an empty slot. It wears a subtype in the slot the snapshot has shown it worn in, else the slot the Supplies reference gives listed armor and accessories, else the one learned by trying once. Each slot compares like with like: learned hits (`weapon_damage`, `damage_saved`) on the hostile types both items have measured, weighted by the threat table, else both shop prices (the starting knife counts as 0); with neither, nothing swaps, and a swap needs more than a 25% gain. A refused `Arm`, `Wear` or `Remove` is not retried for that item and slot until the loadout or inventory changes; a `not_wearable` try is not retried for that subtype for the run. Food, potions, and compose fragments stay for **Heal** and **Solve**.

## Strategist

The AI planner that owns the goal stack (A35, `strategist.py`). It is on in every live run; `run --no-planner` (or `AGENTREALM_NO_PLANNER=1`) is a test mode that plays the built-in plan from `policy.goals`; it answers an op's `no_way_on` itself by exploring round the cell the ask came from (A120). With the planner on and no key, startup fails with one line.

| Variable | Default | Meaning |
|---|---|---|
| `AGENTREALM_PLANNER_PROVIDER` | `anthropic` (`openai` when only an OpenAI key is set) | `anthropic` (official `anthropic` SDK) or `openai` (chat completions over stdlib `urllib`) |
| `AGENTREALM_PLANNER_ANTHROPIC_KEY`, else `ANTHROPIC_API_KEY` | (none) | Anthropic key, from the environment only; the planner's own name first, since some hosts strip the standard one |
| `AGENTREALM_PLANNER_OPENAI_KEY`, else `OPENAI_API_KEY` | (none) | OpenAI key, the same way |
| `AGENTREALM_PLANNER_MODEL` | `claude-sonnet-5-5` for anthropic; required for openai | Model id |
| `AGENTREALM_PLANNER_EFFORT` | `low` | Anthropic effort level |
| `AGENTREALM_PLANNER_REPLAN_S` | 15 | With no event, replan this long after the last call ended (its reply applied, kept, dropped or failed; A83) |
| `AGENTREALM_PLANNER_CALLS_PER_MIN` | 6 | Calls in any 60 s of play, failed ones included |
| `AGENTREALM_PLANNER_TOKENS_PER_MIN` | the larger of 40000 and 1.5 times the cached prefix (about 102k) | Uncached input (cache writes included) plus answer tokens in any 60 s of play; cache reads are not counted (A62). Cost estimate in PLAN.md A62 |
| `AGENTREALM_PLANNER_REFERENCE_SECTIONS` | (core, then the rest under about 60k tokens) | Which parts of the game reference go in the prompt: `all`, `core`, or a comma list added to the core (A62) |
| `AGENTREALM_PLANNER_HURT_FRACTION` | 0.5 | Health below this share of max raises `hurt` |
| `AGENTREALM_PLANNER_IDLE_MINUTES` | 10 | No applied Step for this long raises `idle` |

Besides the stack, State tells the planner whether the character stands on safe ground (`safe_ground`), how far and which way the nearest known safe tile (`nearest_safe`) and the town (`town`) are, and, once, what its previous reply had rejected and why (`last_reply_rejected`), and the ops that stalled, with why (`stalled_ops`, A104). The prompt's prefix says what each survival param means and which way tightens it.

Triggers: an op done or dropped, an op moved below another after it stalled (`goal_stalled`, A104), a navigation give-up (`stuck`), a death, `hurt`, Heal out of food, with no potion due (`heal_supplies`, counting the potions held back, A96), a new clue, every change of map or level (`map`, re-entry included), a directives `goals` change, `idle`, and the `timer` (`AGENTREALM_PLANNER_REPLAN_S` after the last call ended, so a slow reply never sets it off at once, A83). Any of them sends a call as soon as none is in flight and the budget allows; the budget is a rolling minute, so a long session never runs dry. Before play the planner makes one check call; a key the provider refuses (HTTP 401 or 403), or a model it does not know (any other 4xx but 429), stops the run with exit 2 and one line. A failed call keeps its triggers for the next one and keeps the stack, and the next call waits 2 s, doubling with each failure in a row up to 120 s. Acceptance runs count planner errors (failed calls, replies that are not JSON or hold only invalid ops) and accepted plans (at least one valid op, or an explicit empty stack), print both, and fail on 3 errors in a row, a refused key, or, with the planner on, no accepted plan. The prompt is a cached system prefix (the game reference, `docs/GAME_NOTES.md`, the progression stages, then the op contract; A62) and a user message with the triggers, state, stack, clues and directives instructions. The prompt and the reply go to the trace, the prefix as its size and sha256 digest. A reply's `params` merge in at once, key by key, and may only tighten survival params past the directives file's values. Its `goals` become the stack, less any op that finished or was dropped while the call was out and that the reply only carried over from the stack it was shown, and a new `buy` on top counts from what was held when the planner asked (free-play run 7); a reply without a `goals` key keeps it, a stack equal to the current one (ops compared without their `why`; an empty reply on an empty stack too) keeps its progress (a timer reply does not restart a `wait`, the stall clock or the path), and the same op on top keeps its own. A reply that is not a JSON object keeps the stack and is retried after the backoff, as a failed call is (A82). A reply with no valid goal clears the stack: the planner layer emits nothing and the dispatcher's safe default runs (exploring in safe ground, A61). `wait` needs a `why` and at most 30 s. Directives `goals` always win over the planner: their ops left stay on top, and the reply's goals go below them. The op table (`plan.OP_FIELDS`) is the contract: when the planner needs something new, add an op and the state that runs it. To use another provider, write a class with the same `complete(messages)` and `check()` methods as `OpenAIChatClient` and pick it in `make_client`.
