# Character files and state behavior

This page holds the per-policy and per-state detail for the reference agent. For architecture and backlog, see [`PLAN.md`](../PLAN.md). For a short overview, see [`README.md`](../README.md).

## Quick start details

`create` prints a new character id (A59); nothing is written under `python/.state/` for that. `run` drives one character until Ctrl-C: one line per window to stdout and a JSONL trace at `python/.state/<profile>.<character_id>.trace.jsonl`. Pass `--character-id` or `--character-name`, or set `AGENTREALM_CHARACTER_ID`; a flag overrides the environment. `metrics` takes a trace path, or a profile plus `--character-id`, and summarizes the last run in that trace (deaths, kills, gems, levels cleared, time per level; PLAN.md A41); the trace keeps every run, and each starts at its `world` record. To compare two runs or two commits, keep trace paths or metrics JSON snapshots and run `compare-metrics`; it prints candidate-minus-baseline deltas (PLAN.md A42). A positive `deaths` delta means the candidate died more; a positive `time_per_level` delta means it took longer on a level both runs cleared. A level cleared in only one run has a `null` delta, as does `gems` when either run never saw a value.

Characters in the same world share one learned knowledge file at `python/.state/worlds/<world_code>.json` (gitignored): `run` loads it once at start, refusing to start if it is unreadable, and saves it once at exit. Its `items` section holds, per `supply_subtype_code`, weapon reach from a `target_out_of_range` rejection, shop prices seen, and `weapon_damage`: per `npc_type_code`, the largest single hit we have seen this weapon land on that NPC type, counted only when the hit can only be ours. Damage is rolled and depends on the target's defense, so it is a lower bound on the weapon's best hit against that type, not the weapon's damage stat (PLAN.md A18). Its `entrances` section holds one row per minimap entrance mark, keyed `"<map_id>:<x>,<y>"`, with what a look found there (`looked`, `block_type`, `locked`, `needs`); a file from before map-keyed rows is rekeyed once at load (PLAN.md A30).

For worn armor, `items` also holds, per `npc_type_code`, `damage_taken` (the largest hit taken with that item as the only worn piece) and `damage_without` (the largest hit taken with nothing worn, after our `Remove` took that item off, until the next loadout change, death or map change). `damage_saved` is their difference, recomputed whenever either changes. Hits in a response where the worn loadout changed are not counted (PLAN.md A18).

Run one `run` process per world at a time; two would each save their own copy, and the last to exit wins. Stopping the agent leaves the characters in the world where they stand. The game runs at 10 ticks per second; PLAN.md **Real time** says how the agent keeps up.

## Make a character

Copy a file from `python/characters/` and edit it. Names must be unique in the world.

| Key | Meaning |
|---|---|
| `name`, `avatar`, `model_agent`, `world` | Identity. `avatar` is an outfit code. `model_agent` is what rankings aggregate on. |
| `policy.kind` | `idle` sends nothing. `wander` takes random steps. `scripted` runs the reflexes and goals below through the state machine (A5). Before each `POST tick`, a priority dispatcher picks **Sync**, **Downed**, **Escape**, **Retreat**, **Heal** when hurt and no hostile is in range (A10), **Fight** when the win estimate clears `fight_margin` (A23), **Flee**, **Recover**, **Equip** when a held item beats what is worn or armed (A19), **Loot**, **Shop** (A21), **Investigate**, **Solve** (when the plan's top op is `compose` or `use_block`, A39), **Gather**, **Travel** (when directives name a destination), **Boss** (when the plan's `fight_boss` preconditions are met or a boss fight is on, A38), **Level** (on a level interior map, A37), **OddBreak** (A31), **Explore**, or **Idle**, and that state returns the intents to send. **Break** (A28, A31) runs when stuck escalation reaches step 2 or the plan's top op is `break_block`, arming a held capability and `Use` on the nominated cell; failed `(block, capability)` pairs are remembered for the run. **OddBreak** (A31) breaks an odd block the detector scores in sight; it runs only below **Level**, just above **Explore**, so curiosity never preempts Solve, Gather, Travel, Boss or Level, and it ranks weapon breaks ahead of ones that use up a tool; consumable tools only when a clue on that map names the block type; a cell a break ever opened is never tried again, and the target is dropped when it leaves sight or the map, stops scoring odd, or has no route 3 times. If a state's guard holds but it sends no intent this window, dispatch falls through to the next state (A44), so the agent does not freeze waiting on a higher priority that has nothing to do; a state that means to wait (Sync, Downed, Idle, a Flee or Heal wait, Recover opening the chest) marks its outcome `wait` and keeps the round. **Escape** steps off `avoid_blocks` ground; it never breaks blocks. **Retreat** walks to the nearest known safe tile when the next `retreat_hits` hits from the hostiles in range (sized by the threat table) could kill, or when the win estimate says the group outclasses us; it needs a hostile in range and a known safe tile, and never runs with `on_hostile = "ignore"`. During a boss fight **Retreat** and **Flee** stand down: **Boss** walks back toward the boss door instead, unless no step toward it is open or the clock is nearly gone, and then it fights on (PLAN.md A38). **Fight** closes to weapon reach, `Use`s an NPC by id (the server finds its block on the tick the swing runs) or a character directly, and queues retreat steps behind the swing when a safe tile is known; it never runs on a safe tile, when `would_lose` is true, or when the target is out of weapon reach with no open step closer, and then **Flee** runs instead. **Flee** carries out `policy.on_hostile` below and stays put on a known safe tile (A9). It commits to a multi-step escape rather than one greedy step per decision: the best single step first (ties toward a known safe tile; standing still when cornered), then a route to that safe tile, or up to 6 seen cells away from the hostiles when none is known; it keeps walking it until it arrives, the next cell is shut or would land nearer a hostile than the best single step, or Flee stops. **Investigate** (A30) reads each readable cell (sign, statue) in sight and says hello once to each NPC within 25 blocks from where it stands, and walks next to each minimap entrance mark and each door with no recorded warp on any map the knowledge file knows except level interiors (through known door warps when needed, under the curiosity cap) to record what terrain shows (`block_type`, `locked`; a locked one needs a key); the knowledge file remembers reads, speech, and entrance looks, and a target refused 3 times is dropped for the run. |
| `policy.goals` | Tried in order: `explore`, `doors`, `goto` (with `policy.goto = [x, y]`, optional `policy.goto_map = <map_id>` for another map), `wander`, `hold`. Paths may run through unseen ground (fog costs 2 per step to known ground's 1), but the agent only steps onto tiles it has seen; a goal whose next step is unseen yields to the next goal. A search that runs out of its node budget (`goto` on its own map, the death chest) plans only the steps inside perception, along a coarse corridor over 16×16 map tiles that is searched a little each replan and kept until the goal or map changes or a step is rejected. With a shared knowledge file, door warps and terrain are remembered across runs; `goto_map` routes through known doors, then A* on each map. The `doors` goal prefers doors whose destination is not yet recorded. A rejected step teaches the map by code (a `not_traversable` cell stays blocked until a `BlockChanged` on it, a `block_occupied` cell is skipped one move then priced high for 30 ticks, a locked door is marked `locked` on its door entry in the knowledge file; PLAN.md reflex 1 has the full table). When progress toward a target on the current map stalls (the remaining path not shortening in 20 moves or 30 s, oscillation, 3 rejected moves in a row, or no route), the agent replans with fog de-prioritized, may **Break** a nominated obstacle when it holds an untried capability, then walks up to 40 moves toward the reachable frontier nearest the target to reveal a way round, then tries a door-graph route only, then gives up with exponential backoff (300 ticks, doubling) and queues a `stuck` signal for the strategist (A15, A28, A35). Each step runs only after the one before has failed on its own window. At step 2 only, breakables on the straight route can be planned through at a break step cost (weapon cooldown plus one, plus tool price when not a weapon), and the weapon armed before a break is re-armed once it opens the block. Capabilities come from the manual's per-class rules on the exact codes in GAME_NOTES, or from breaks a subtype already opened. This covers Explore's goals and plan ops, Travel and the death-chest walk, including the map leg toward a known door when the goal is on another map; with no known route there, the goal yields without a backoff. A frontier given up on is skipped by `explore` and `explore_area` until its backoff ends. |
| `policy.on_hostile` | `flee`, `fight`, or `ignore`, for anything in `policy.hostile` (`npc`, `character`) within `policy.hostile_range`. `fight` swings at hostiles not in `never_attack` when the win estimate clears `fight_margin`, and flees when it would lose, the target is forbidden, or the target is out of weapon reach with no open step closer. |
| `policy.pickup` | **Loot** (A20): walks to free supplies in sight and takes them (`Take`), and withdraws the best supply from a ground chest within reach (`WithdrawFromChest` with that one id). With the carried chest full (10 slots, counting held, worn, armed and stowed), it drops the lowest-valued held supply first, but only for a pickup worth more; otherwise it skips the pickup and lets **Explore** run. Value is extra lives (once the ground code is known), then free gems (`gem`), then the item table's `gem_price`, then potions and food, then anything else. Priced supplies are the shop's and the death chest is **Recover**'s. A `carry_capacity_full` rejection lowers the assumed capacity to what is carried; buying a `middle_chest` or `red_chest` raises it to the Manual §16 cap (30, 100), an assumption until measured. A `Drop` refused `not_transferable` is never retried, and stowed supplies are never dropped. Hearts first starts once a life's ground code is learned: when `lives` rises in a response whose only applied `Take` was one supply, that code is kept in the knowledge base as a life (A47). |
| `policy.avoid_blocks` | Block types to step off and to plan around. Standing on one with no safe step off, the plan crosses as few as it can. Other fire and lava cost their `occupy_damage` per step. |
| `policy.entity_refresh` | Ticks between entity reads when nothing is happening. |
| `policy.seed` | Random seed for `wander`. Defaults to the character id. |

**Oscillation guard** (A15, A58). Two states can take turns moving the character: one steps it east, the next decision another steps it back, and it paces between two cells. Each state on its own sent a sensible step, so no state can see this. Dispatch checks for it once per decision, before any state runs (`navigation/oscillation.py`): when the character stood on at most 2 distinct cells over its last 6 cell changes (standing still is not counted), it gives up the target it was walking to through stuck detection's step 5 (backoff of 300 ticks doubling on each give-up, a `stuck` signal with reason `pacing`), writes an `oscillation` event to the trace, and lets dispatch pick again. It does not matter which states caused the pacing, so a new state needs no special case for it. After each decision dispatch notes which walk the move belonged to (the goal of `Memory.path` when the step lands on its next cell). A target is given up only when its own walk made one of the pacing moves, so survival states (Retreat, Fight, Flee, Heal) pacing on their own never back off a goto or explore target left over from earlier; the trace still records the event and which states moved. When only Flee and Retreat did the pacing, the event carries `escape: true` and the guard hands them the paced cells: the next Flee plans a fresh escape that keeps off them, and the next Retreat routes around them. This is separate from the per-attempt oscillation check in stuck detection, which only sees one goal's own steps and escalates a level.

Each profile may also have `python/characters/<profile>.directives.toml` beside it. The runner re-reads it when the file changes; a file that fails to read or parse keeps the last good directives (defaults if none loaded yet); deleting the file restores the defaults. `never_attack` lists kinds or NPC type codes the agent must not swing at (`character`, or an NPC `code`); a fight reflex that would `Use` a forbidden target flees instead, and any other `Use` aimed at one is replaced by a `Wait`. A `Use` on the character itself (**Heal** eating or drinking) is not an attack and always passes. `params` tune survival: `retreat_hits`, `risk`, and `lives_floor` set when **Retreat** fires from health and the threat table; `fight_margin` scales the win estimate **Fight** and **Flee** gate on (A23). `curiosity` (default 0.2) caps how many of the last 600 ticks **Investigate** walk-to-look detours and future **Break** queues may cover; **Read** and **Say** from where the agent stands are always free (A30). The window is not reset on a map change or death. Out-of-range param values are ignored. `goals`, when set, replace the goal stack: shorthand like `gather_gems:20` or `buy:bronze_mail` becomes typed plan operations validated against the strategist op table (A34). A reload with the same `goals` keeps the stack's progress and the current path; changed `goals` restart the stack and drop the current path, so the new top op replans at once. **Explore** follows a path only while it belongs to the stack's top op (same op, same target); when the top op changes, even to another op of the same kind, it replans. With no valid `goals` (none set, or every entry invalid, which is logged), the stack mirrors `policy.goals` one for one. `explore_area`, `travel` (to an entrance, town, shop, or a point), `wait`, `compose`, `use_block`, `buy` (via **Shop**, A21), and `fight_boss` (via **Boss**, with optional `min_health`, `min_potions`, `armed`, and `worn` preconditions) run from the stack today; any other op (for example `travel` to a hunting ground) is dropped with a log line when it comes up, and an op with no path for 30 seconds is dropped too. A stack `travel` to a shop with `x = 0, y = 0` means the nearest known shop cell (a shop at the map origin cannot be named); it is done on a priced supply or on that cell, even bought out. With other `x, y` it walks to that cell and is done there. **Solve** handles `compose` once every fragment is held (one per slot), and `use_block` by arming the named supply in hand and `Use` on the block (walking into reach first); `use_block` is done once the target's block type changes, and then Solve re-arms what was armed before (once, if still in hand). A `compose` or `use_block` op that makes no progress for 30 seconds (pieces or supply missing, target unreachable, or a `Compose`/`Use` that changes nothing) is dropped with a log line; until then the states below get the round. While the top op has no path, `policy.goals` get the move, and the path one of them sets is kept until it goes stale. `wait` seconds count at the world's tick rate. `travel:town`, `travel:hunting_ground`, `travel:shop`, `travel:entrance:x:y` or `travel:point:x:y` (optionally `map_id:x:y`) in `goals` are not stack ops: **Travel** (A27) reads them straight from `goals` and visits them in order, routing with the cost grid and door graph; a destination the agent cannot place yet (no shop seen, no eligible hunting ground) is skipped while Explore runs, and dropped once a later one is travelled to. Hunting grounds closed by `over_strength_ceiling` reopen when the loadout changes (PLAN.md A27). On a level interior map, **Level** walks toward unexplored doors (then frontier tiles when no door is reachable) before **Explore**. Directives still apply inside a level: a `travel:*` destination that resolves outranks **Level**, so a `travel:town` walks the agent out; **Level** resumes once it is reached or while no destination resolves, and with no door or frontier in reach it yields the round to the states below it. A `goals` entry like `gather_gems:20` also runs **Gather** (A22), read straight from `goals` rather than from the stack, once a snapshot has reported the gem counter, until it reaches 20: it `Use`s the grass it stands on and adjacent bushes in safe-ish ground (known safe zones, cells touching one, or within the town respawn probe ring, with no hostile in range), walking to the nearest such cell. With nothing to gather in sight it steps aside for **Explore**; with targets in sight but none reachable it stays out for 10 ticks. It also walks to free ground supplies whose code matches authored gem piles (`gem` in Olympuff; GAME_NOTES.md) and `Take`s them before grass and bushes. `instructions` are kept for the strategist (A35).

In a calm window it would otherwise skip, the agent calls `get_zone` on one revealed cell: first within 8 blocks of town or its last respawn point, then on the cells of its planned path. It records which are safe for retreat (A9), **Heal** (A10) and death-chest recovery (A11). When hurt and out of combat, **Heal** walks to or takes food in sight, then `Arm` + `Use` self on carried food or a potion; once nothing is left to drink it re-`Arm`s the weapon that was swapped out (once, even if health is already full or a hostile is in range), rests in a safe zone once health has been seen coming back there, otherwise waits in town and raises a `buy` signal for potions that **Shop** (A21) reads. Heal amounts and whether a food heals on pickup are learned into the item table from health changes; nothing reads them yet. With no reachable known safe tile, or after 600 ticks of waiting with no health back, it yields to Explore for 300 ticks.

With `policy.pickup` on, **Recover** walks back to a dropped death chest on this map only once a safe tile on or next to it is known; until then, or while no step toward it can be planned, it keeps exploring. At the chest it withdraws everything when it all fits, else the best supplies by id that fit; it drops held junk first when the pack is full and the chest beats what is carried; otherwise it skips a withdraw that would only repeat `carry_capacity_full`. Only that tile is checked, not the route to it. **Escape**, **Retreat**, **Fight** and **Flee** outrank it, and the pickup reflex still runs first. Urgent windows and the `idle` policy never read zones.

**Equip** (A19, A55) runs when something in hand clearly beats the weapon or armor already in that slot, or when something in hand has no known worn slot yet: it `Arm`s a better weapon, `Remove`s a worn piece and `Wear`s the upgrade, or tries a single `Wear` on a held non-weapon never seen worn (priced or not) so the next snapshot's `worn` teaches the slot. It arms only the weapon codes GAME_NOTES names, and only while the armed slot holds a weapon or nothing and Heal, Solve or Break is not using it. It wears a subtype only in a slot the snapshot has shown that subtype worn in (learned by trying once when needed). Each slot compares like with like: learned hits (`weapon_damage`, `damage_saved`) on the hostile types both items have measured, weighted by the threat table, else both shop prices (the starting knife counts as 0); with neither, nothing swaps, and a swap needs more than a 25% gain. A refused `Arm`, `Wear` or `Remove` is not retried for that item and slot until the loadout or inventory changes; a `not_wearable` try is not retried for that subtype for the run. Food, potions, and compose fragments stay for **Heal** and **Solve**.

## Strategist

An optional LLM that rewrites the goal stack when something happens (A35, `strategist.py`). It is off unless both are set:

| Variable | Default | Meaning |
|---|---|---|
| `AGENTREALM_STRATEGIST_MODEL` | (none) | Model name sent to the OpenAI chat completions API |
| `AGENTREALM_STRATEGIST_API_KEY` or `OPENAI_API_KEY` | (none) | API key |
| `AGENTREALM_STRATEGIST_MIN_INTERVAL_S` | 60 | Seconds between calls |
| `AGENTREALM_STRATEGIST_MAX_CALLS` | 48 | Calls per run |
| `AGENTREALM_STRATEGIST_MAX_TOKENS` | 200000 | Prompt plus answer tokens per run; multiply by your model's price for a dollar cap |
| `AGENTREALM_STRATEGIST_IDLE_MINUTES` | 10 | No applied Step for this long raises the `idle` trigger |

Triggers: a new clue, a navigation give-up (`stuck`), a death, entering a level, a plan op finished or dropped, and `idle`. Every call counts toward the limits, failed ones included, and a failed call keeps its triggers for the next one. The prompt and the reply go to the trace. A reply's `params` merge in at once, key by key (a key it leaves out keeps its value), and may only tighten survival params past the directives file's values. Its `goals` replace the goal stack, unless none is valid or directives `goals` are set, which always win over the strategist. With the strategist off, triggers are logged and dropped, and clues still steer **Explore** (A32). To use another provider, write a class with the same `complete(messages)` method as `OpenAIChatClient`.
