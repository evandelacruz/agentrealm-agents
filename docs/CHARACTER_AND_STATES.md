# Character files and state behavior

This page holds the per-policy and per-state detail for the reference agent. For architecture and backlog, see [`PLAN.md`](../PLAN.md). For a short overview, see [`README.md`](../README.md).

## Quick start details

`create` prints a new character id (A59); nothing is written under `python/.state/` for that. `run` drives one character until Ctrl-C or SIGTERM, then parks it on safe ground for up to `--park-seconds` and clears its queue (A66; README **Stopping a run**): one line per window to stdout and a JSONL trace at `python/.state/<profile>.<character_id>.trace.jsonl`. Pass `--character-id` or `--character-name`, or set `AGENTREALM_CHARACTER_ID`; a flag overrides the environment. `metrics` takes a trace path, or a profile plus `--character-id`, and summarizes the last run in that trace (deaths, kills, gems, levels cleared, time per level; PLAN.md A41); the trace keeps every run, and each starts at its `world` record. To compare two runs or two commits, keep trace paths or metrics JSON snapshots and run `compare-metrics`; it prints candidate-minus-baseline deltas (PLAN.md A42). A positive `deaths` delta means the candidate died more; a positive `time_per_level` delta means it took longer on a level both runs cleared. A level cleared in only one run has a `null` delta, as does `gems` when either run never saw a value.

Characters in the same world share one learned knowledge file at `python/.state/worlds/<world_code>.json` (gitignored): `run` loads it once at start, refusing to start if it is unreadable, and saves it once at exit. Its `items` section holds, per `supply_subtype_code`, weapon reach from a `target_out_of_range` rejection, shop prices seen, and `weapon_damage`: per `npc_type_code`, the largest single hit we have seen this weapon land on that NPC type, counted only when the hit can only be ours. Damage is rolled and depends on the target's defense, so it is a lower bound on the weapon's best hit against that type, not the weapon's damage stat (PLAN.md A18). Its `entrances` section holds one row per minimap entrance mark, keyed `"<map_id>:<x>,<y>"`, with what a look found there (`looked`, `block_type`, `locked`, `needs`); a file from before map-keyed rows is rekeyed once at load (PLAN.md A30).

For worn armor, `items` also holds, per `npc_type_code`, `damage_taken` (the largest hit taken with that item as the only worn piece) and `damage_without` (the largest hit taken with nothing worn, after our `Remove` took that item off, until the next loadout change, death or map change). `damage_saved` is their difference, recomputed whenever either changes. Hits in a response where the worn loadout changed are not counted (PLAN.md A18).

Run one `run` process per world at a time; two would each save their own copy, and the last to exit wins. Stopping the agent leaves the characters in the world where they stand. The game runs at 10 ticks per second; PLAN.md **Real time** says how the agent keeps up.

## Make a character

**Some behavior runs only for plan ops the planner emits** (A61, A35): equipping gear (`equip`) and restocking potions (`buy`), which M8 checks; reading signs and greeting NPCs (`read`, `say`), which M10 checks; and walking to look at entrance marks (`travel`), which M9 checks. With `--no-planner` nothing emits them. `buy:<code>` and `travel:*` can go in directives `goals` by hand (a `buy` buys one more of its item, whatever is already held); `equip`, `read` and `say` have no shorthand and wait for the strategist.

Copy a file from `python/characters/` and edit it. Names must be unique in the world.

| `policy.kind` | `idle` sends nothing. `wander` takes random steps. `scripted` runs the state machine (A5): AI plans, state machine executes (PLAN.md **Architecture**, A61). Before each `POST tick` a priority dispatcher runs the first state that acts. **Reflexes** act on what is happening now, whatever the plan says: **Sync**, **Downed**, **Escape**, **Retreat**, **Heal** when hurt and no hostile is in range (A10), **Fight** when the win estimate clears `fight_margin` (A23), **Flee**, **Pickup** (a worthwhile supply underfoot or adjacent, A20), **Recover** (A11), **Detour** (A71: with `policy.pickup` on, a free gem, a life, or food while hurt that comes into view, priced by the steps going by it adds to the route still ahead (queued steps included) from where the character stands, at most 8 for a gem pile (4 more for each pile next to it, up to 16), 16 for a life and 4 for food (A73), on ground clear of known hostiles, is walked to and taken, and the walk then resumes toward its target) and **Greet** (A65: one `Say` hello to the nearest likely helper in sight not yet spoken to; the API names no helpers, so that is an NPC that has stood on one cell for 5 s in view and has not hit us, and none is greeted off safe ground while `policy.hostile` names NPCs; never with a threat near or under a `say` op; it never walks, fires only at a decision window so it never drops a running walk queue, and an applied hello lands the NPC in `greeted_npcs`, so each is greeted once; that record is Greet's own, so a later `say` op to the NPC still says its text and a refused hello spends none of the op's refusals). After the run stops, in the park phase only, the survival reflexes run and then **Park**, which walks Retreat's way to safe ground (A66). Retreat, Park and Heal walk only to a safe cell outside every known hostile's ground, in view or remembered (a hostile Retreat runs from holds only the cells it gets to before we do), and Flee runs toward the same cell Retreat picks, so the two never pull opposite ways (free-play run 7); nothing else runs. **Executors** run only for the plan's top op: **Equip** (`equip`, A19), **Loot** (`fetch_item`), **Shop** (`buy`, A21), **Investigate** (`read`, `say`, A30), **Break** (`break_block`, and stuck escalation step 2 of the walk under way, A28), **Solve** (`compose`, `use_block`, A39), **Gather** (`gather_gems`, A22), **Travel** (`travel`, A27), **Boss** (`fight_boss` when its preconditions hold, or a boss fight on, A38), **Level** (`enter_level`, A37), **Wait** (`wait`) and **Explore** (`explore_area`). Explore comes last and is also the **safe default**: with no plan op, or when the op's executor has nothing to do this decision, it explores safe ground (off hazards, away from hostiles, inside safe zones when hurt), and with nothing left to explore it steps to a safe neighbour, so a decision is never idle. Exactly one state picks the movement target at a time, and it commits to it (A71): a grass cell, frontier, safe tile, shop cell, door or supply, once picked, is kept until reached or gone, proven out of reach, or the plan op changes, never re-picked because another came nearer; a target with no path that is not proven walled in is escalated by stuck detection and let go after 10 decisions in a row, and Gather waits at most 5 s on a first step another occupant holds before it picks again. A prerequisite (an item a locked entrance needs, matched exactly) is a stop walked to first, and the target stays; with no room for it, or after 3 refused `Take`s, the stop is given up. Each state keeps its commitment under its own key (`python/agentrealm_agent/targets.py` lists them). A new head op from the planner takes over once the action under way ends. If a state's guard holds but it sends no intent, dispatch falls through to the next (A44); only forced waits keep the round with no intent (Sync, Downed, a Flee wait, Recover opening the chest, Boss on the door, and the plan's `wait`). **Escape** steps off `avoid_blocks` ground; it never breaks blocks. **Retreat** walks to the nearest known safe tile a path reaches (one walled in or given up on is skipped), else the town cell, as one walk queue, taking the shortest way past the hostiles it runs from, when the next `retreat_hits` hits from the hostiles in range (sized by the threat table) could kill, or, with `on_hostile = "fight"`, when the win estimate says the group outclasses us and it is coming for us (hit us recently, in reach, approaching, or a boss; A9); it needs a hostile in range and somewhere safe to head for: a safe cell outside every known hostile's ground, in view or remembered, where a hostile it runs from holds only the cells it gets to before we do; with none, it sends nothing and **Flee**'s escape runs; it never runs with `on_hostile = "ignore"`. During a boss fight **Retreat** and **Flee** stand down: **Boss** walks back toward the boss door instead, unless no step toward it is open or the clock is nearly gone, and then it fights on (PLAN.md A38). **Fight** closes to weapon reach, `Use`s an NPC by id (the server finds its block on the tick the swing runs) or a character directly, and queues retreat steps behind the swing when a safe tile is known; it never runs on a safe tile, when `would_lose` is true, or when the target is out of weapon reach with no open step closer, and then **Flee** runs instead. **Flee** carries out `policy.on_hostile` below and stays put on a known safe tile (A9). It commits to a multi-step escape rather than one greedy step per decision: the best single step first (ties toward Retreat's refuge, the safe cell outside hostile ground that Retreat walks to; standing still when cornered), then a route to the refuge when every cell of it is reached before any hostile could get there, else up to 6 seen cells away from the hostiles under the same rule; it keeps walking it until it arrives, the next cell is shut or would land nearer a hostile than the best single step, or Flee stops. With `on_hostile = "flee"`, the hostile that hit us in the last 30 ticks (named by the `Damaged` event's `source_id`) is fled even just past `hostile_range` while it is in view; other hostiles past range are not. Only a hostile's hit counts: an `Attacked`, or a `Damaged` from an NPC or character, never a trap or hazard ground. Running must work: once such a hit lands after Flee began, or the gap to the nearest hostile has not grown over 30 ticks, Flee fights back when we win (the weapon has hurt that type and the win estimate clears) or, above the health floor, it is cornered, else walks Retreat's way to safety, else, above the health floor, swings back at the hitter while it keeps hitting us and is in weapon reach (never a `never_attack` target) (A9). |
| `policy.goals` | Input to the built-in planner, used only in the `--no-planner` test mode when directives set no `goals`: each becomes one plan op. With the AI planner on (A35) the stack starts empty and the planner fills it. `explore` → `explore_area` anywhere, `doors` → `travel` to the nearest door, `goto` (with `policy.goto = [x, y]`, optional `policy.goto_map = <map_id>` for another map) → `travel` to that point. No state reads `policy.goals` (A61). A `goto` already stood on gets no op when the plan is rebuilt, so it is not walked back to (A16); only a change to `policy.goto` or `policy.goto_map` makes it owed again. Paths may run through unseen ground (fog costs 2 per step to known ground's 1), but the agent only steps onto tiles it has seen. A search that runs out of its node budget plans only the steps inside perception, along a coarse corridor over 16×16 map tiles that is searched a little each replan and kept until the goal or map changes or a step is rejected. A corridor is kept per plan and per danger profile: Retreat's walk (shared with Fight's retreat tail) and its losing-ground replan each keep their own, because a finished corridor is searched again only when a tile on it gets dearer, never cheaper. A state that holds its own queue while it runs returns `wait` and not a reflex, so the runner's reflex probe leaves that queue running instead of replacing it every round trip; Retreat does this (A9), and another state can reuse the pattern. With a shared knowledge file, door warps and terrain are remembered across runs; a cross-map `travel` routes through known doors, then A* on each map. A rejected step teaches the map by code (a `not_traversable` cell stays blocked until a `BlockChanged` on it, a `block_occupied` cell is skipped one move then priced high for 30 ticks, a locked door is marked `locked` on its door entry in the knowledge file; PLAN.md reflex 1 has the full table). When progress toward a target on the current map stalls (the remaining path not shortening in 20 moves or 30 s, oscillation, 3 rejected moves in a row, or no route), the agent replans with fog de-prioritized, may **Break** a nominated obstacle when it holds an untried capability, then walks up to 40 moves toward the reachable frontier nearest the target to reveal a way round, then tries a door-graph route only, then gives up with exponential backoff (300 ticks, doubling) and queues a `stuck` signal for the strategist (A15, A28, A35). Each step runs only after the one before has failed on its own window. At step 2 only, breakables on the straight route can be planned through at a break step cost (weapon cooldown plus one, plus tool price when not a weapon), and the weapon armed before a break is re-armed once it opens the block. When the window search finds no cell better than where the agent stands, that is no route, never a step away and back. A frontier given up on is skipped by `explore_area` and the safe default until its backoff ends. **The walker commits to its path** (A15, `navigation/walk.py`): every walk (Explore's goals and plan ops, Travel, Recover, Level, Investigate, Boss, Heal, Loot) follows the path it chose until it arrives, a step on it is rejected, its target changes, or newly seen terrain blocks it or makes another path more than 20% cheaper. It does not re-pick its route every decision, so two equal routes never alternate: the one being walked wins. Explore keeps heading for the frontier it was exploring: while its target is still a frontier cell it keeps the walk, and when a reveal takes that cell away it re-aims at the nearest frontier ahead, so a reveal that makes the other side's frontier the nearest does not turn it round. A direction clue is the exception: when a sign or NPC names a side where the walk could go (frontier it may pick, such as inside an `explore_area` op's area, and reachable), a walk heading elsewhere is dropped at once and Explore walks to the clue's side (A32); a clue pointing only at ground it could not pick leaves the walk alone. A kept path whose next cell is still unseen waits for it to be seen (Travel holds the round for at most 5 s at one cell, then lets the safe default move), and a new path that starts by stepping back to the cell just left is taken only when the kept one is blocked (A58 run 5, where fog showing the other route one tile at a time turned the goto walk round). |
| `policy.on_hostile` | `flee`, `fight`, or `ignore`, for a hostile of a `policy.hostile` kind (`npc`, `character`) within `policy.hostile_range`. A character counts by kind; an NPC counts once its type has swung at us, hit us or died in view, this run or an earlier one (kept in the world knowledge base), or when it is a boss or the one hitting us (`survival.is_hostile`), so townsfolk and helpers are never fled, retreated from or fought, and never block a cut, repel a path, close a frontier or raise the poll rate. `flee` runs a committed escape, and once the escape fails (a hit lands after Flee began, or the gap stops growing over 30 ticks) it fights back, retreats to a known safe tile, or swings back at the hitter (A9). `fight` swings at hostiles not in `never_attack` when the win estimate clears `fight_margin`, and flees when it would lose, the target is forbidden, or the target is out of weapon reach with no open step closer. |
| `policy.pickup` | **Pickup** (A20, a reflex): takes a worthwhile free supply underfoot or adjacent (`Take`), and withdraws the best supply from a ground chest within reach (`WithdrawFromChest` with that one id). With the carried chest full (10 slots, counting held, worn, armed and stowed), it drops the lowest-valued held supply first, but only for a pickup worth more; otherwise it skips the pickup. Value is extra lives (once the ground code is known), then free gems (`gem`), then the item table's `gem_price`, then potions and food, then anything else. It never walks: walking to a supply further away is **Loot**'s, for a plan `fetch_item` op. Priced supplies are the shop's and the death chest is **Recover**'s. A `carry_capacity_full` rejection lowers the assumed capacity to what is carried; buying a `middle_chest` or `red_chest` raises it to the Manual §16 cap (30, 100), an assumption until measured. A `Drop` refused `not_transferable` is never retried, and stowed supplies are never dropped. Hearts first starts once a life's ground code is learned: when `lives` rises in a response whose only applied `Take` was one supply, that code is kept in the knowledge base as a life (A47). |
| `policy.avoid_blocks` | Block types to step off and to plan around. Standing on one with no safe step off, the plan crosses as few as it can. Other fire and lava cost their `occupy_damage` per step. |
| `policy.entity_refresh` | Ticks between entity reads when nothing is happening. |
| `policy.seed` | Random seed for `wander`. Defaults to the character id. |

**Oscillation guard** (A15, A58). A safety net: with one state picking the movement target at a time (A61) it should not fire. Two states could take turns moving the character: one steps it east, the next decision another steps it back, and it paces between two cells. Each state on its own sent a sensible step, so no state can see this. Dispatch checks for it once per decision, before any state runs (`navigation/oscillation.py`): when the character stood on at most 2 distinct cells over its last 6 cell changes (standing still is not counted), it gives up the target it was walking to through stuck detection's step 5 (backoff of 300 ticks doubling on each give-up, a `stuck` signal with reason `pacing`), writes an `oscillation` event to the trace, and lets dispatch pick again. It does not matter which states caused the pacing, so a new state needs no special case for it. After each decision dispatch notes which walk the move belonged to (the goal of `Memory.path` when the step lands on its next cell). A target is given up only when its own walk made one of the pacing moves, so Retreat, Fight and Flee pacing with steps of their own never back off a goto or explore target left over from earlier; the trace still records the event and which states moved. Heal's and Loot's walks are stuck attempts of their own, so when they pace, the guard gives up their food, pickup or safe tile. When only Flee and Retreat did the pacing, the event carries `escape: true` and the guard hands them the paced cells: on that same decision Flee plans a fresh escape that keeps off them, or Retreat routes around them; the next decision drops them either way. This is separate from the per-attempt oscillation check in stuck detection, which only sees one goal's own steps and escalates a level.

Each profile may also have `python/characters/<profile>.directives.toml` beside it. The runner re-reads it when the file changes; a file that fails to read or parse keeps the last good directives (defaults if none loaded yet); deleting the file restores the defaults. `never_attack` lists kinds or NPC type codes the agent must not swing at (`character`, or an NPC `code`); a fight reflex that would `Use` a forbidden target flees instead, and any other `Use` aimed at one is replaced by a `Wait`. A `Use` on the character itself (**Heal** eating or drinking) is not an attack and always passes. `params` tune survival: `retreat_hits`, `risk`, and `lives_floor` set when **Retreat** fires from health and the threat table; `fight_margin` scales the win estimate **Fight** and **Flee** gate on (A23). The win estimate weighs ticks for the hostiles to kill us against ticks for us to kill them, both sides' swings priced by the published roll: ours at the world's base attack power of 2 (a hit 65% of the time, for 1 up to 2 plus the armed weapon's damage; the pocket knife 1–4), a measured hostile's with its largest hit as its attack power, while a type never measured lands every swing for the conservative default (A81). At the default margin the knife takes one weak measured hostile at full health and refuses a pair or an unmeasured type. `curiosity` is kept for the strategist; no state reads it (A61). Out-of-range param values are ignored.

`goals`, when set, are manual steering: they go on top of the plan stack and outrank the strategist, which plans below them; once each is done or dropped, the strategist owns the stack. A program can add goals on top of the file's without writing it (`CharacterConfig.pinned_goals`; the M7 smoke pins its target this way); each is pinned once, so after its op is done or given up a reload never brings it back. A `travel` op of any `to` (point, town, shop, hunting ground, an entrance with a cell; not an `entrance` at `0, 0`, the nearest unexplored door) whose destination resolves to a cell stuck detection gave up on leaves the stack for good, pinned or the planner's; the planner's prompt lists those cells, and a reply that sends a travel there again is filtered out (A16). The planner sees the stack with each op marked `pinned` or `planner`, and is told it cannot remove pinned ops, only plan below them (A35). Shorthand `gather_gems:20`, `buy:bronze_mail` and `travel:<to>[:[map_id:]x:y]` (`town`, `hunting_ground`, `shop`, `entrance`, `point`) become typed plan operations validated against the strategist op table (A34). A reload with the same `goals` keeps the stack's progress and the current path; changed `goals` restart the stack and drop the current path and every committed walk (A15). With no valid `goals` (none set, or every entry invalid, which is logged), the built-in planner builds the stack from `policy.goals`. Each op runs only in its executor (see `policy.kind`); finished ops pop, ops no state carries out (`hunt`, `avoid`) are dropped with a log line, and an op whose executor makes no progress for 30 seconds is dropped too, while the safe default moves. A `travel` to a shop or entrance with `x = 0, y = 0` means the nearest known one; `travel:town` and `travel:hunting_ground` take no cell; a destination the knowledge base cannot place yet sends nothing and stalls, except a `hunting_ground`, which explores while spare windows read zones for one, until it finds one, the frontier runs out, or 300 s pass (A27). A plan `travel` op needs `x`, `y` only for a `point`. Hunting grounds closed by `over_strength_ceiling` reopen when the loadout changes (PLAN.md A27). **Gather** (`gather_gems`) waits for a snapshot to report the gem counter, `Use`s the grass it stands on, never a bush, since bushes drop berries, not gems (A81) (arming a held tool that cuts first when the armed item is not known to cut, and arming the weapon it swapped out again once no `gather_gems` op is on top) on known ground off hazards, with no known hostile near: within 6 blocks of the one that hit us, within a step past weapon reach or `hostile_range` of any other (the survival states keep it alive in the field). Hostiles out of view count too: it remembers where each was last seen (for 600 ticks), the post a guard stands on, and how far from that post one has hit the character, keeps off that ground, and takes no target whose path still crosses a known hostile's reach, so a hit on the way to a pile drops that pile; a `gather_gems` with `fight: true` gathers there anyway (Detour obeys the same tests). A hostile within 6 blocks for 15 s without attacking is fought when `on_hostile = fight` and the win estimate passes, else Gather walks in one go to ground 12 blocks from it, and `Take`s free gem piles (`gem` in Olympuff; GAME_NOTES.md) first, walking to the nearest known such cell; with no pile it walks to the nearest grass by walk. It cuts field cells before safe-zone ones; safe zones stay eligible, since breaking works there. It skips cells it cut too recently to have grown back (600 ticks) or whose last `Use` had no effect (held out 600 ticks, never filed as a cut), and after 3 no-effect cuts in one region or one safe zone (Break's capability probes, and cuts made with an item known not to cut such as a potion, do not count) it treats that whole region or zone as uncuttable for a while. In run 2 every cut on town grass had no effect (GAME_NOTES.md), which is what this learns. With none known while standing on safe ground it heads out to the nearest known field cell, else the nearest frontier; only with nowhere to head does it explore for one. It leaves grass alone in a region its own cuts showed barren (16×16 blocks with no gem after 15 cuts, which ground at the manual's 20% would almost surely have broken; A63, A81) unless the op names that region with optional `x, y` (`gather_gems` with `count, x, y`); every cut and whether a gem came of it is kept per map in the world knowledge base, and the planner's State shows the map's measured yield (`expected_yield`), the best regions at any distance (with `distance` in blocks) and the barren ones nearby as `gem_yield`, plus Gather's last decision as `gather_status` (`cutting`, `taking a gem`, `walking to grass`, `walking to a gem pile`, `moving off from a hostile that shadows`, `fighting a hostile that shadows`, `blocked by hostile`, `cuts have no effect here`, `heading out of safe ground`, `no cuttable cell in view`, `region barren`, `walking to a target region`; any but `cutting` ends in `, no cut for N s` after 30 s with no cut, and ` (region x,y)` while Gather works only in a target region) and this run's `gather_run` (`cuts`, `no_effect_cuts`, `gems_gained`). That `x, y` names a target region: Gather walks there and cuts only there while it knows a cell to cut there, walks to gem piles only there (one in reach is taken anyway), and it lifts that region's barren mark. Without one, once its region shows a poor yield after a fair sample (20 cuts, under half the map's measured yield, `expected_yield`), Gather walks to the best region within 64 blocks that gave at least `expected_yield` and leaves poor regions alone while one is known. **Solve** handles `compose` once every fragment is held (one per slot), and `use_block` by arming the named supply in hand and `Use` on the block (walking into reach first); `use_block` is done once the target's block type changes, and then Solve re-arms what was armed before (once, if still in hand). Only a step counts as progress for Solve and Break, so a `Compose` or `Use` that changes nothing cannot pin the stack. **Investigate** walks into reach and sends the op's `Read` or `Say`; the knowledge file remembers reads and speech, and an op refused 3 times is finished. A `say` names its NPC by `npc_id` or `npc_type` (the nearest of that type in sight). The planner's State lists the nearest 5 NPCs in sight as `nearby_npcs` (id, type, distance and direction, whether a `say` op spoke to it, whether Greet greeted it, whether known hostile, whether it stays put), `npcs_spoken_to` and `npcs_greeted`, and a helper's reply reaches it as an `npc` clue (A65). **Level** walks to the `enter_level` entrance, then toward the level's unexplored doors (then frontier tiles), and finishes the op when no step is left. **Equip** applies the best upgrade each decision until none is left. `wait` needs `why` and at most 30 seconds, counted at the world's tick rate. `instructions` are kept for the strategist (A35).

In a calm window it would otherwise skip, the agent calls `get_zone` on one revealed cell: first within 8 blocks of town or its last respawn point, then, while **Travel** searches for a hunting ground none is known for, one cell in every 4 × 4 square of its view (A27), then on the cells of its planned path. A terrain read's `safe` flag already marks safe-zone cells, so those are known safe without a zone read and never probed; their brightness is then never read and counts as 1. It records which are safe for retreat (A9), **Heal** (A10) and death-chest recovery (A11). When hurt and out of combat, **Heal** walks to or takes food in sight, then `Arm` + `Use` self (target `{"kind": "self"}`) on carried food or a potion, both in one paced queue; on its next decision it re-`Arm`s a weapon, before anything else: the one the drink swapped out, else the last one armed this run, never a potion or tool (once, even if health is already full or a hostile is in range). Then it walks to a known safe tile; in a safe zone it samples regen while it walks to the zone's own unexplored edge, never out of it, saving a "yes" to the knowledge file; with no such edge left it sends `Wait` and starts no walk, so walking out and back can never cut the sample short and a long rest leaves stuck detection untouched. A food `Take` or a drink the server rejects is handled by the rejection's code, with no try cap (A80): nothing armed, arm it and drink again; the supply gone or not carried, forget it; a `Take` out of reach, walk onto the food first; dead or on a cooldown, try again a weapon cooldown (1 s) later; anything else, an unknown code included (traced as `heal_refusal`), not again until where it stands, what it holds or arms, its max health, or the food's cell changes (health alone moves too often to count). A drink whose `Use` applied but left the supply carried, with no `SupplyUsed` of ours for it and no health back, drank nothing, and the next decision reads why (A76, traced as `heal_noop`): something else in the armed slot, arm it and drink again (or, if that drink already sent its `Arm`, hold it); full health, not again until health is below that reading; armed, hurt and nothing changed, not again until the map, the supply ids it carries or its max health change, or health falls below that reading, so a potion is never unusable while health falls. The armed supply is read by id from the snapshot's `inventory.armed`: a drink of a potion while another of the same code is armed sends its `Arm` first, and a potion left armed is still drunk even if `held` leaves it out. Only server rejections are filed, from any state (Pickup's refused food `Take` and Retreat's drink included), never a drink decided while a queue was held and not sent (free-play run 5). Once this run has measured no regen there, Heal never samples or walks to a safe zone again: it asks the planner once for food and potions (a `heal_supplies` trigger, raised again only after a full heal) and sends nothing, so the plan's executor or the safe default moves. Heal amounts and whether a food heals on pickup are learned into the item table from health changes; nothing reads them yet. Each walk to food or a safe tile, and each **Loot** walk to a pickup, gives its target up (backoff 300 ticks, doubling) when there is no route or the remaining path has not shortened in 20 moves or 30 s, or it paces; the next food, carried supply or safe tile is tried instead (`pathing.bounded_step`, A15). A walk whose first step is taken or unseen waits, and is given up after 30 s of waiting, timed from when the wait began. A walk's 30 s clocks run only while it is pursued decision after decision: one Heal or Loot left and later takes up again starts them afresh, and its record is cleared once its food or pickup is in reach to take.

With `policy.pickup` on, **Recover** walks back to a dropped death chest on this map only once a safe tile on or next to it is known; until then, or while no step toward it can be planned, it sends nothing and the next state moves. At the chest it withdraws everything when it all fits, else the best supplies by id that fit; it drops held junk first when the pack is full and the chest beats what is carried; otherwise it skips a withdraw that would only repeat `carry_capacity_full`. Only that tile is checked, not the route to it. **Escape**, **Retreat**, **Fight**, **Flee** and **Pickup** outrank it. Urgent windows and the `idle` policy never read zones.

**Equip** (A19, A55) runs for a plan `equip` op, and acts when something in hand clearly beats the weapon or armor already in that slot, or when something in hand has no known worn slot yet: it `Arm`s a better weapon, `Remove`s a worn piece and `Wear`s the upgrade, or tries a single `Wear` on a held non-weapon never seen worn (priced or not) so the next snapshot's `worn` teaches the slot. It arms only the weapon codes GAME_NOTES names, and never while Heal, Solve or Break is using the armed slot; otherwise a potion or tool left there counts as an empty slot. It wears a subtype only in a slot the snapshot has shown that subtype worn in (learned by trying once when needed). Each slot compares like with like: learned hits (`weapon_damage`, `damage_saved`) on the hostile types both items have measured, weighted by the threat table, else both shop prices (the starting knife counts as 0); with neither, nothing swaps, and a swap needs more than a 25% gain. A refused `Arm`, `Wear` or `Remove` is not retried for that item and slot until the loadout or inventory changes; a `not_wearable` try is not retried for that subtype for the run. Food, potions, and compose fragments stay for **Heal** and **Solve**.

## Strategist

The AI planner that owns the goal stack (A35, `strategist.py`). It is on in every live run; `run --no-planner` (or `AGENTREALM_NO_PLANNER=1`) is a test mode that plays the built-in plan from `policy.goals`. With the planner on and no key, startup fails with one line.

| Variable | Default | Meaning |
|---|---|---|
| `AGENTREALM_PLANNER_PROVIDER` | `anthropic` (`openai` when only an OpenAI key is set) | `anthropic` (official `anthropic` SDK) or `openai` (chat completions over stdlib `urllib`) |
| `AGENTREALM_PLANNER_ANTHROPIC_KEY`, else `ANTHROPIC_API_KEY` | (none) | Anthropic key, from the environment only; the planner's own name first, since some hosts strip the standard one |
| `AGENTREALM_PLANNER_OPENAI_KEY`, else `OPENAI_API_KEY` | (none) | OpenAI key, the same way |
| `AGENTREALM_PLANNER_MODEL` | `claude-sonnet-5-5` for anthropic; required for openai | Model id |
| `AGENTREALM_PLANNER_EFFORT` | `low` | Anthropic effort level |
| `AGENTREALM_PLANNER_REPLAN_S` | 15 | With no event, replan this long after the last call ended (its reply applied, kept, dropped or failed; A83) |
| `AGENTREALM_PLANNER_CALLS_PER_MIN` | 6 | Calls in any 60 s of play, failed ones included |
| `AGENTREALM_PLANNER_TOKENS_PER_MIN` | the larger of 40000 and 1.5 times the cached prefix (about 102k) | Uncached input (cache writes included) plus answer tokens in any 60 s of play; cache reads are not counted (A62). Cost estimate in PLAN.md A62 |
| `AGENTREALM_PLANNER_REFERENCE_SECTIONS` | (core, then the rest under about 60k tokens) | Which parts of the game reference go in the prompt: `all`, `core`, or a comma list added to the core (A62) |
| `AGENTREALM_PLANNER_HURT_FRACTION` | 0.5 | Health below this share of max raises `hurt` |
| `AGENTREALM_PLANNER_IDLE_MINUTES` | 10 | No applied Step for this long raises `idle` |

Besides the stack, State tells the planner whether the character stands on safe ground (`safe_ground`), how far and which way the nearest known safe tile (`nearest_safe`) and the town (`town`) are, and, once, what its previous reply had rejected and why (`last_reply_rejected`). The prompt's prefix says what each survival param means and which way tightens it.

Triggers: an op done or dropped, a navigation give-up (`stuck`), a death, `hurt`, Heal out of food and potions with no regen (`heal_supplies`), a new clue, every change of map or level (`map`, re-entry included), a directives `goals` change, `idle`, and the `timer` (`AGENTREALM_PLANNER_REPLAN_S` after the last call ended, so a slow reply never sets it off at once, A83). Any of them sends a call as soon as none is in flight and the budget allows; the budget is a rolling minute, so a long session never runs dry. Before play the planner makes one check call; a key the provider refuses (HTTP 401 or 403), or a model it does not know (any other 4xx but 429), stops the run with exit 2 and one line. A failed call keeps its triggers for the next one and keeps the stack, and the next call waits 2 s, doubling with each failure in a row up to 120 s. Acceptance runs count planner errors (failed calls, replies that are not JSON or hold only invalid ops) and accepted plans (at least one valid op, or an explicit empty stack), print both, and fail on 3 errors in a row, a refused key, or, with the planner on, no accepted plan. The prompt is a cached system prefix (the game reference, `docs/GAME_NOTES.md`, the progression stages, then the op contract; A62) and a user message with the triggers, state, stack, clues and directives instructions. The prompt and the reply go to the trace, the prefix as its size and sha256 digest. A reply's `params` merge in at once, key by key, and may only tighten survival params past the directives file's values. Its `goals` become the stack, less any op that finished or was dropped while the call was out and that the reply only carried over from the stack it was shown, and a new `buy` on top counts from what was held when the planner asked (free-play run 7); a reply without a `goals` key keeps it, a stack equal to the current one (ops compared without their `why`; an empty reply on an empty stack too) keeps its progress (a timer reply does not restart a `wait`, the stall clock or the path), and the same op on top keeps its own. A reply with no valid goal clears the stack: the planner layer emits nothing and the dispatcher's safe default runs (exploring in safe ground, A61). `wait` needs a `why` and at most 30 s. Directives `goals` always win over the planner: their ops left stay on top, and the reply's goals go below them. The op table (`plan.OP_FIELDS`) is the contract: when the planner needs something new, add an op and the state that runs it. To use another provider, write a class with the same `complete(messages)` and `check()` methods as `OpenAIChatClient` and pick it in `make_client`.
